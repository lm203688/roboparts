- 补写必须按 L1.40 RECONCILED 规格：标补写者、正文含免责声明「据 git 痕迹重建」、

## 首跑失败根因（真实缺陷，不是网络抖动）
- 首跑在 `11af550` 处被 tree 一致性闸拦下，**远端未被污染**（PATCH 在最后一步，失败时 ref 未动）。
- 根因：默认 `core.quotePath=true` 时 `git diff-tree` 把非 ASCII 路径输出成
  octal 转义（`"RoboParts-\344\272\247…"`），脚本 `pathRaw.replace(/^"|"$/g,'')` 只去引号**不解码**，
  把字面 `\344` 当路径上传 ⇒ 错误 tree。`11af550` 是区间内首个触碰非 ASCII 路径的提交
  （含中文命名的 7MB mp4），故前 5 个提交全对。
- 修法：`git -c core.quotePath=false diff-tree` + 新增 `unquotePath()`（quotePath=false 后仍可能
  双引号包住的 C 风格转义路径，按 JSON 语法解，失败退化为裸去引号）。
- **教训通用化**：凡是解析 git 输出的路径字段，都要显式关掉 quotePath 或显式解码 octal；
  只去引号是错的。

## 推送工具加固：--dry-run 预检
