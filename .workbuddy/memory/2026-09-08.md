## GPT-6×KiCad 事实核查 + 电气接口第二判定轴（17:07 轮）
- **事实核查结论**：OpenAI GPT-6 Astra 官宣 KiCad 演示**为真**（2026-09-07），但走 computer-use 操作 GUI，**非官方集成**。能力边界一手：社区复现六层 CM5 双 NVMe 载板 2h20m/15% 周额度/第 5 版仍未完成，且大量依赖 Freerouting；EEBench（atopile 团队，13 项 SPICE + 最恶劣容差角）最强 Claude Opus 5 **61.6%**（Grok 4.6 57.1% / Fable 5.1 56.4% / GPT-5.5 42.3% / GPT-5.6 Sol 39.4%），**GPT-6 Astra 尚无成绩**。⇒ "代替电路设计"是夸大，近四成设计不可投产。
- **判断（给了用户反直觉建议）**：**不做 PCB 设计**。能力栈（SI/PI、EMC、DFM、安规）+ 责任栈完全不同；atopile(MIT, YC W24, Tesla/DJI/Lilium 团队, 带 MCP server) + KiCad MCP 生态(kicad-copilot/tylerwagler 75 工具) + Quilter($40M) 已免费/开源铺完这条路。真机会：AI 画板瓶颈不是"画"而是**选对件并确定它们能连**（EEBench 失败集中在容差角与选型/成本博弈）→ 定位为 **AI-PCB 流水线的「机电接口规格上游」**，只出规格不出 Gerber（不背"板子炸了"的责）。与 Tnkr 结论同构：成为生态一环而非自开产品线。
- **落地**：`api/reference_builds.json` 的 RB-OMY/RB-ODM 新增 `electrical_interface` 段（供电轨/总线/连接器/电平/判定）；`reference-builds.html` 同步渲染（含判定色点）。新增 `docs/kicad-ai-integration-20260908.md`。
- **一手核实电气事实**：Dynamixel T 结尾=**TTL 3-pin（JST EHR-03 / B3B-EH-A / SEH-001T-P0.6 / 21AWG）**；R 结尾 + P 系列=**RS-485 4-pin（JST EHR-04 / B4B-EH-A）**；Feetech STS3215=**5264-3P**（Pin1 GND/Pin2 VCC/Pin3 Signal，半双工 38400bps~1Mbps）；官方 NOTE 推荐电路按 **5V/5V-tolerant MCU** 设计，3.3V 主控需 Level Shifter；供电经 Pin1(−)/Pin2(+)。
- **⚠️ 暴露责任缺口（重要）**：`XM430-W350-T`(TTL 3-pin, 10~14.8V) 与 `PH54-200-S500-R`(RS-485 4-pin, 24~48V) **同为 DYNAMIXEL Protocol 2.0**，现有协议级判定显示**兼容**，但实际①针数不同②供电轨不同，**共链可能损坏器件**。同类：Feetech 5264-3P(2.54mm) 与 Dynamixel JST EHR-03(2.5mm) 同为 3-pin 但不兼容且外观相似易误插。
