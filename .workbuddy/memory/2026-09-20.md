**踩坑**：第一次 `git commit` 后 `git add -A` 只 stage 了 M，D 未 stage（`env -u`
在 Git Bash 里不存在，删文件的 python 未执行，但 git add 之后 index 里
只留下 M；后续 `git add -A` 也未把之前 D 重新 stage，因为 D 已经被 index 视为
"未变化"）。第二次显式 `git add -A` 才把 D 纳入 index，单独 commit。
教训：**删除操作完成但 status 显示 "no changes" 时，别急着 commit，先看
`git status` 全量输出**——`git commit` 不会自动 stage 工作树的删除，
只提交 index 里的内容。

**踩坑 2**：`git commit --amend --message=...` 在 Git Bash 里把消息当成
pathspec（`--message=` 空值 + 后续被解析为路径）。可靠写法：
`git commit --amend -F -` + `subprocess.run(input=msg)`。

**踩坑 3**：远端 tree 校验用 `curl` 时必须用 `Authorization: Bearer <token>`，
不是 `token <tok>`；`.git-credentials` 格式 `https://x-access-token:<tok>@github.com`
要正则提取，不能按 `@` 后 `:` 前简单切分。
