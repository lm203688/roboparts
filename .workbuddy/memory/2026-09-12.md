### 关键教训（务必跨会话记住）
1. **部署挂死根因**：`deploy.mjs` 的 `[1/3]` `spawnSync(npx wrangler pages deploy)` 在本机**无限挂死**（wrangler 进程 CPU=0 冻结，与脚本注释 08-18「卡 18 分钟」同形）。根因：① deploy.mjs **从不读 .env.local** → `CLOUDFLARE_API_TOKEN` 未进环境 → wrangler 退回**已过期 OAuth**；② `npx` 路径本身挂死；③ CF API 本身可达（<1s）⇒ 非网络封锁。
   **已修（源码 `7fd827f`）**：`loadDotEnvLocal()` + 无 `WRANGLER_BIN` 时优先**全局 wrangler**（`%APPDATA%\npm\node_modules\wrangler\bin\wrangler.js`，node 直跑绕开 npx）+ wrangler `spawnSync` 加 8min 硬超时。直跑验证 EXIT=0。
   **诊断手法（可复用）**：`spawnSync` 会缓冲输出到进程退出才打印 → 「日志不动」≠ 挂死；用 **PowerShell `Get-Process -Id <pid>).CPU` 采样 6–8 秒看增量**：CPU 增=在算/在传；CPU 恒 0=阻塞等待。再用进程命令行 `Win32_Process.CommandLine` 找到真的 wrangler 子进程。
2. **锁**：sandbox 里 `acquire` 管道到不存在的 `tail` 被打断 → 留下「心跳新鲜、PID 已死」的自锁（脚本按心跳判持有，不判 PID）→ `release --force` 后干净重取。判死命令也别信 `os.kill(pid,0)`（Win 报 WinError 87），用 ctypes OpenProcess 或 tasklist。
3. **sandbox shell wrapper PATH 残缺**：`head`/`tail`/`dirname`/`ls` 常 not found → **别用管道到这些**；改写文件到项目内路径 + Read/Grep 工具读取。
4. **`/tmp` 陷阱**：bash 的 `/tmp` 与 Windows python 的 `/tmp`(=C:\tmp) 不是同一处 → 用项目内相对路径。
5. **日报 stamp 时间禁写未来**：`_last_digest.txt` 若写未来时刻 → evaluate 判 ok=False → verdict 落 skipped → 与「到期」矛盾被拒。写当前（过去）时刻。
