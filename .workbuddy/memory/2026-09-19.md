## 外部项目扫描：7 项对 RoboParts 的借鉴评估（联网实搜，非记忆）
用户问 pyroki / ego-mc-bench / connexus / modar / ericbuess / inverse kinematics / mecka 有无借鉴与可对接。逐项核实：

- **pyroki**（PyRoki，UC Berkeley，MIT，IROS 2025，1.4k★，`chungmin99/pyroki`）：JAX 可微分运动学工具包——URDF→FK/IK + 自动碰撞体(capsule) + LM 求解器 + 轨迹优化/动作重定向，CPU/GPU/TPU 通吃，比 cuRobo 快 1.4–1.7×。**Tier1 可直接集成**：给 RoboParts 的"机械接口判定"往上加一层"装配链可达性/自碰撞"判定（新 MCP 工具）。局限：只有软约束、无采样规划器、碰撞仅 sphere/capsule/halfspace/heightmap、仅运动学树（无闭环/并联）。
- **inverse kinematics**：技术域非项目；实现候选 pyroki / cuRobo / Pinocchio / PyBullet。前提是零件要有 URDF/关节元数据——正撞本项目"声明率 5.75%"的缺口，只能对有运动学元数据的件生效。
- **connexus**（两个不同物）：①`@agentic-conexus/mcp`、`@coderampart/conexus`——Go 写的"agentic context engine" MCP（语义+BM25 混合检索、evidence-backed validation、context_search 等工具）；②**RTI Connext MCP**——厂商把自家权威知识做成 MCP server 给编码 agent 用，实测 17% 更快、省 ~66k token（对比无 MCP）。②最像 RoboParts 的范式：**Tier2 最高价值借鉴**＝"厂商/权威方 MCP＝权威领域知识"叙事 + 量化收益证明。
- **ericbuess**（Eric Buess，Claude Code/MCP 社区个人开发者）：`claude-code-docs`(≈947★ 文档镜像)、`claude-code-project-index`、`limitless-ai-mcp-server`。**Tier2 分发打法借鉴**：做"所有人都链接的 canonical 索引/镜像"（对应：人形零件索引/ISO 9409-1 与厂商 datasheet 镜像）。
- **mecka**（Mecka AI，2024 成立）：众包自我中心(egocentric)人体动作数据训人形机器人，Framework 领投 $60M、传红杉领投 ~$500M 估值；Egoverse 开放数据集；自我定位"physical AI 的数据与部署层"。**Tier3 战略相邻**：他们收"动作数据"、我们收"零件数据"，同栈相邻层 ⇒ 潜在合作/客户；学"开放数据集当名片"（RoboParts 开放数据已在做）。注意 adjacency 反向侵入风险。（另 mecka.com 是无关的汽配电商 SaaS，别混。）
- **modar**（ModAR，CMU，arXiv 2609.17524）：Modality-Autoregressive World-Action 模型，30.1M 参数胜过 6B 视频模型；预测点轨迹/DINO 特征/深度优于 RGB。**Tier3 情报信号**：无集成，只作前沿信号喂飞轮（可推"哪类零部件会热"）。
- **ego-mc-bench**（Ego-MC-Bench / Ego-CoMist，Qualcomm，arXiv 2606.09547）：厨房第一视角视频"即时纠错"基准，区分**预判式(anticipatory) vs 事后式(post-error)**反馈；SOTA 视频 LLM 干预 F1 仅 0.18。**Tier3 弱相关**：无集成；只借"预判式 vs 事后式"框法讲兼容检查（下单前预警 vs 装完才报错）。

## GeneTech/SwarmLabs 14 站数据接入评估（一手探针，裁决：不接入）

收到推广称 embodied-ai 子站 "~47k 实体" + `api.swarmlabs.tools/v1/oss/registry` + Pro ¥39.9 语义搜索 + `slb_` 独立 key。实测：

- **静态数据可用**：`lm203688.github.io/genetech-14-sites/.../entities.json` → **301** → `data.swarmlabs.tools/...`（**200**，`Content-Length 20265240`＝20.3 MB，HTTP/HTTPS 均通，Last-Modified 2026-09-19 12:36 GMT）。直连可拉，但约 **42 KB/s**（全量需约 8 分钟）。
- **动态 API 不可用**：`api.swarmlabs.tools/v1/oss/registry` 经代理 502、直连 21s 超时、WebFetch 走公网得 Cloudflare **522**（边缘可达、源站未响应）。无静态镜像（`data.../oss/registry.json` 404）。
- **规模口径乱**：子站目录索引 `.../embodied-ai/website/api/` 自报 `totalEntities: 10000`；同一站点首页自称 **"30 个领域 / 300000 条"**；推广文案写 "~47k"（该数字与本项目记的 **SwarmLabs 飞轮 47,566** 吻合 ⇒ 主站数字被套用到子站）。我取前 2 MB 样本解析 1,210 条，均值 1.65 KB/条 ⇒ 线性外推 ≈1.2 万，与索引自报 10,000 同量级、与 47k 差 3.9×。
