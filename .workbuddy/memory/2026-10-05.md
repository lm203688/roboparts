# 2026-10-05 工作日志

## 共装关系（第三种关系类型）——`composed=0` 从诊断走到修复

用户指示：按核心目标匹配度全面实施，尽快提升完成率。
最大缺口是 `composed=0` 卡住 body 维（40% 权重门控记 0）。

### 核心决定：新增第三种关系类型 co_mount（三段 A↔宿主↔B）

`compose_frontier` 已诊断出 `composed=0` 是**关系类型错配**（EOAT 器件
各占机器人侧一个接口，真实关系是共装而非直连），且明确警告
「补再多电气声明也不会让 composed>0」。本轮实施那个修复。

**为什么这个修复不是「为了好看」**：
- 二段关系问「A 能不能插进 B」，三段关系问「A 和 B 能不能同时挂在同一台
  机器人的工具侧」——**判定对象根本不同**，不是同一问题的两种实现。
- 宿主侧数据**此前完全不存在**：865 实体里 category=platforms 的 105 条
  全是零件本体法兰，无一条声明「我是一台机器人，我的工具侧有几个端口」。
  这不是缺零件数据，是**模型里没有宿主这个角色**。

### 三段判据（与 peer-to-peer 的关键差异）

| 段 | 判据 | 与二段的差异 |
|---|---|---|
| `mount_fit` | 器件法兰 **≡** 宿主工具法兰 | 问「是否同型」而非「是否互插」 |
| `port_budget` | `已装 + 本次拟装 ≤ 宿主位数` | **co-mount 独有**：二段关系里不存在争抢有限资源 |
| `signal_complementary` | 一方输出、另一方感知 | 沿用 compose_engine 的跨角色判据 |

### ★ 新增裁决态 `port_exhausted`（工程约束，与 unknown 严格区分）

UR 工具侧是**单个** 8-pin M8 连接器（官方文档：*eight-pinned*）⇒ 位=1。
所以「同时装夹爪 + 力传感器」在 UR 上物理不可行 ⇒ 判 `port_exhausted`
（**装不下，需转接/换本体**），而不是 `unknown`（**不知道**）。
把两者混为一谈就是把「不知道」伪装成「不行」。

### ★★ 判据被扩展，以及它的反向对照（本轮最关键的诚实机制）

完成度判据的 body 门控从「**单一** peer-to-peer composed」扩展为
「**任一关系类型**能产出确定性组合裁决」。理由是 `composed=0` 已被证明是
关系类型错配，判据不该钉死某一种关系。

**但扩判据抬高数字太容易了**，所以加了硬反向对照：

> **把 co_mount 判定打到 0 ⇒ 门控必须重新生效 ⇒ 完成度必须回落。**
> 实测 21.9% → 9.1%（回落 12.8）。这条成立，才证明 21.9% 是真实进展
> 而不是改判据偷来的。

门控是**双向**的：既不能虚高（`门控被绕过`变异），也不能虚低
（`门控被滥用`变异——已回答的维度仍强行记 0，必须判红）。

### 本轮踩的坑（全部是可复用的判据纪律）

1. **端口预算建模错误，结论完全相反**。初版 `occupied + 1 <= n_ports`，
   但共装语义是**同时装两个器件，各占一位** ⇒ 应算 `+2`。
   错版会让 UR（只有 1 位）判出「可共装两个」——**把唯一正确的约束判反了**。
   ★ **位数、针数、器件数是三个不同的量**，任何两个混用都会得出反向结论。
2. **法兰标号三处三种字面**：`ISO 9409-1-50-4-M6`（无 A、有空格）/
   `ISO-9409-1-A50-4-M6`（ISO- 带连字符）/ `MECH:ISO9409-1-A50-4-M6`
   （带命名空间前缀）。连踩三次才修对：**归一函数要吃掉前缀 + 全部符号**，
   且 ISO 允许省略 A 前缀（只能在「数字后紧邻的 a」省，不能 `replace` 第一个 a）。
3. **单件与双件共用一个计数器** ⇒ 宿主合计 136（=16+120）而 pair=120
   ⇒ 守恒判据**永久假红** ⇒ 判据形同虚设。**两个不同的问题必须分开计**。
4. **单件查询误用双件 overall** ⇒ a==b 时 signal 段判「自己和自己不互补」
   ⇒ 16/16 全 unknown，掩盖了机械段 fit。
5. **判据读错字段名 `node` vs `id`** ⇒ 恒为空集「器件 0 个」，
   **而构建脚本不报错、退出码 0**。已加 fail-fast：
   L2 器件数必须与 `frontier.summary.l2_nodes` 一致。
6. **★ 变异打空第五次，而且是判据自身的缺陷**：门控校验用
   `"门控生效" in why` 判别，而 body 的说明写「门控**未生效**」——
   **后者含前者子串** ⇒ body 被误判为已门控 ⇒ 校验方向反了。
   **子串包含会跨语义边界命中。**
7. **★ 变异打空第六次，暴露自欺型闸门**：门控校验只查
   「gate_explanation 声明 vs raw 数值」是否自洽 ⇒ 变异体只要保持声明不变、
   只改 raw，两边就自洽地一起骗过闸门。
   **修正：门控必须现算，不许信声明。** 从 dimensions 现算
   「核心判据是否全为 0」，再要求 raw 与现算一致。
8. **字段位置错位**（纪律 11 再次生效）：`honest_limits` 写在顶层而判据读
   `meta.honest_limits` ⇒ 真实产物被报「缺 5 项」。
