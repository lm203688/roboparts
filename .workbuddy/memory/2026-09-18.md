### 坑：LobeHub `lhm login` 的 OAuth 回调只绑 IPv6 回环（已修）

第一次 `lhm login` 失败，用户明确说"完成授权了"但 CLI 报 `Login failed: Missing code or state in callback`。

**根因**：CLI 把回调监听的 socket **只绑在 `[::1]:51234`**（netstat 实测，`TCP [::1]:51234 LISTENING`，IPv4 侧无监听），而它的 `redirect_uri` 写死 `http://localhost:51234/callback`。浏览器解析 `localhost` 走了 **IPv4 127.0.0.1** → 撞死端口 → 授权页显示"无法访问此网站"，CLI 干等到 5 分钟超时。CLI 无 `--host`/`--port` 选项（`login --help` 只有 `--base-url`），所以无法从 CLI 侧规避。

**我犯的错（记录以免重犯）**：诊断时我直接 `curl http://[::1]:51234/callback` 探活 —— 该监听是**单次性**的，这个不带 code/state 的裸请求被当成真正的回调受理，直接终结了那次登录流程（报的就是 `Missing code or state`）。**探活 OAuth 回调端口绝不能真发请求**，只能看 netstat。

**解法**：`ops/tmp/oauth_loopback_forward.mjs` —— 在 `127.0.0.1:51234` 起一个纯 TCP 透传（不解析 HTTP），转发到 `[::1]:51234`。顺序必须是**先起 login（占住 ::1:51234）再起转发器**，否则 CLI 可能因端口探测改绑 51235。已自测：dummy v6 echo server + 转发器 + IPv4 客户端，回包 `ECHO:ping` ✓。加转发器后一次登录成功：**`✓ Logged in as lm203688 (61960005@qq.com)`**，凭据有效期至 2026-09-25。

（`github connect` 不踩这个坑 —— 它是浏览器发起 + CLI 每 2 秒轮询状态，不依赖本地回调端口。）

### 发不出去的原因
`mcp-publisher publish` → **401 JWT expired**。`~/.config/mcp-publisher/token.json`（`method=http`，2026-08-06 生成）已过期，而那对 Ed25519 的**私钥全盘搜索无果**；只有公钥还托管在
`https://roboparts.cc/.well-known/mcp-registry-auth`（HTTP 200，`p=2IYjaqqBu8gSSNca0tBBaU1pVCjm3yaEaCRwaw9lbbw=`）。
即：**域名所有权证明还在，签名私钥丢了**。可选修法见 `ops/outreach/mcp-registry-refresh-20260918.md`（方案 A：轮换托管公钥→重新 login http→publish，全程无需浏览器，且可逆）。

### 又一坑：Registry schema 限 description ≤ 100 字符
我改写 server.json 时写成 157 字符，`mcp-publisher validate` 直接 **422 expected length <= 100**。原句 91 字符是当年刻意压过的。
