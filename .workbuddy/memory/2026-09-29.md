## 二、Isaac ROS 5.0（2026-09-22 ROSCon 多伦多发布）

对 RoboParts 的关键信号：

1. **rosidl::buffer** — NVIDIA + Open Source Robotics Alliance 贡献给 ROS Lyrical 的**供应商中立内存传输接口**。让 CPU/GPU/其他加速器内存间零拷贝。
   - 哲学：「保持标准 ROS 消息、发布者、订阅者、节点边界、中间件不变，middleware 实现以 plugin 加载 buffer backend」
   - 对 RoboParts 的启示：**RoboParts 就是数据层的 rosidl::buffer**——保持 URDF/机械接口/电气接口这些「标准消息类型」不动，让任何厂商的兼容性数据以插件形式接入。定位完全一致。
2. **Agent-ready skills**：FoundationStereo 微调 / FoundationPose 5.5x 加速 / pick-and-place 都是可复用的「skill」。NVIDIA 走「让 AI Agent 调用机器人组件」路线。
   - 对 RoboParts：`lint_urdf` 就是 RoboParts 版的 agent-ready skill。MCP 工具面（11 tools）是等价抽象。
3. **生态整合者**：AgenticROS（RealSense 赞助）+ Intrinsic Core + RealSense D585 Pro + Universal Robots AI Accelerator + Mentee Robotics + Robotis + Seeed Studio + Magna + Ekumen。
   - 对 RoboParts：这些都是潜在集成客户。RoboParts 的兼容性数据可以喂给任何其中一家做 pre-flight 检查。

## 三、Feather Robotics（feather.dev）—— 精准目标客户

**Feather Robotics Inc.（2025 年 San Francisco 创立，CEO Hoa Mai，CPO Parsa Bakhtiari）**：
- 轮式双臂人形机器人，105kg，$29,990（$32,990 原价）
- 23 DOF：2×7-DoF 手臂 + 2 颈部 + 1 躯干升降 + 6 全向底盘
- **Custom end effectors supported**（官方明示）+ 6-DoF 手 / 2-finger 夹爪 / 95mm 线性行程
- Open SDK：Python 3.9+ (Apache 2.0) + ROS 2
- Compute：Jetson Nano (标配) / AGX Orin / Thor（客户可换）
- 传感器：Stereolabs ZED 2i / X / X Mini 头部 + 可选腕部相机
- 已交付首单 + 收入破 $1M（2026-09-24 官方）
- 融资：$7.6M pre-seed（Gradient Ventures 领投）+ Builder Capital / Geometry / SEED Innovations / Virgo VC

**战略要点**：
1. Feather 是**目标客户，不是竞品**。他们的定位是「body + open SDK + 让 physical AI 公司专注算法」，RoboParts 的定位是「body 之间的兼容性数据层」。互补不冲突。
2. **每个 Feather 客户都是一次性 BOM 采购**：6-DoF 手 / 夹爪 / 定制末端执行器 / 电池包 / 计算单元 / 相机——每一样都要过机械接口 + 电气接口 + 电气连接器 + 尺寸约束。RoboParts 的 4 维兼容性检查正好卡在他们的选型瓶颈上。
3. Feather 官方没公开 GitHub repo（`github.com/featherrobotics` 显示 "no public repositories yet"）——意味着用户无法从 URDF/xacro 里读机械接口规格，只能靠 datasheet 或 RoboParts 这样的数据层。
4. Feather 说 "custom end effectors supported" 但没有说「怎么判断能装」。这就是 RoboParts 的价值。

## 四、AgenticROS（agenticros.com）—— 竞品也是生态

**AgenticROS**（RealSense 赞助的开源项目）：
- GitHub：https://github.com/agenticros/agenticros
- npm 包：`@agenticros/core`（Apache-2.0，v0.8.9，周下载 128）
- MCP server：`@agenticros/claude-code`（Claude Code / Desktop / Codex CLI / Gemini CLI 都能接）
- 9 个内置 MCP 工具：`ros2_list_topics / ros2_publish / ros2_subscribe_once / ros2_service_call / ros2_action_goal / ros2_param_get/set / ros2_camera_snapshot / ros2_depth_distance`
- 4 种 transport：Zenoh (CDR) / rosbridge (WebSocket) / WebRTC / 本地 DDS
- **Skills marketplace**：`npx agenticros skills install owner/skill-id`，已上架 `chrismatthieu/navigate-to`、`detect-humans`、`start-slam`、`follow-me-ros`、`navigate-through-poses`、`moveit-pick`、`dock-to-charger`
- 每个 skill 声明 `capabilities: [{id, verb, preconditions, inputs, outputs}]`——**这就是 RoboParts entity schema 的镜像**
- Phase 1 已完成：capability registry + skill chaining + multi-robot fleet discovery

**战略含义**：
1. **RoboParts 应该成为 AgenticROS skill**。`npx agenticros skills install roboparts/roboparts`——这是把兼容性检查接入 AgenticROS 的完整生态（OpenClaw + Claude Code + Gemini + Codex）的最短路径。
2. AgenticROS 的 capability schema 和 RoboParts 的 entity schema 可以**互相引用**——比如 RoboParts 的 `check_compatibility` 可以成为一个 AgenticROS skill，AgenticROS 的 `navigate_to` 可以调用 RoboParts 的 `lint_urdf` 做 pre-flight。
3. AgenticROS 是 RoboParts 目前最大的**直接竞品**（都在做 agent ↔ robotics 的数据/能力桥接）——但**规模差距巨大**（AgenticROS 周下载 128 vs RoboParts 29 次调用 0 注册），且他们的市场是 ROS2 部署栈，不是零件兼容性。可以共存。
