兼容性 Agent 架构与诚实度

RoboParts 的兼容性裁决不是"给个分数就完事"——它的核心资产是诚实：判不了就说判不了，绝不把"没数据"伪装成"兼容"或"不兼容"。下面这张架构图与实时指标，是给 AI Agent 与工程师的信任凭证。

🧩 兼容性裁决管线（5 阶段）

① 检索
Retrieve
从归一化实体表按 ID / 品类 / 关键词定位两侧零件
api/entities.json
→
② 匹配
Match
抽取协议 / 电压 / 机械接口 / ROS 四维证据
compat_engine.tokens
→
③ 校验
Verify
四维逐维裁决：共享→兼容；冲突→不兼容；无数据→无法判定
judgePair()
→
④ 生成
Generate
不兼容时生成转接件方案（法兰转接板 STL/OpenSCAD）
adapter-generator
→
⑤ 验证
Validate
装配红线校验 + 安装反馈回流，持续校准置信度
adapter-feedback
全部裁决逻辑收敛于唯一实现 functions/_lib/compat_engine.js（Single Source of Truth）。/api/compatibility、/mcp、BOM 检查器均 import 它，杜绝"同一问题三个答案"的隐性假绿。

🛡️ 诚实度徽章（引擎不变式）

✅
零假绿
未声明数据（null）绝不伪装成兼容（true）。判 true 至少需一项硬约束（协议/电气/机械）有双方声明。
✅
零假红
厂商"未公开"不等于"装不上"。mechanical 维度 348 条 not_declared 不再被误判为不兼容。
📐
Single Source of Truth
裁决逻辑唯一实现，所有通道复用，防止口径漂移。
🔍
缺口诚实披露
机械尺寸级声明率仅 0.57%，逐条显式标注 status，不猜测填充。
🧮
四维裁决
协议 / 电气 / 机械 / 软件，任一维度冲突即判不兼容，否则如实标 null。
