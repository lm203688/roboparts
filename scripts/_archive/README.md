# scripts/_archive — 一次性迁移脚本归档

**目的**：把已经跑完、被后续治理脚本取代的日期化/修复型脚本收拢到这里，避免
`scripts/` 主目录被历史迁移淹没。

**保留原则**：
- **归档 ≠ 删除**：文件仍入库，git 历史完整；`git mv` 保留了可回溯的 diff 路径。
- **可回溯**：每个文件头都带有批次日期（`202608XX`/`202609XX`），必要时可直接查
  `git log --follow <file>` 定位写入批次。

**归档清单（24 个，2026-10-07 归拢）**

| 类别 | 文件 | 说明 |
|---|---|---|
| `curate_*_202608XX` | 3 个 | 机械接口/法兰人工采编批次，已被 `govern_*.py` 系列长期接管 |
| `expand_*` | 3 个 | 实体扩充批次（`expand_entities_20260805` 等），T5 一次性任务后不再复用 |
| `fix_*` | 12 个 | 早期 P0/P1/P2 修复（安全/支付/追溯/去重），对应 bug 已闭合，回归 L1.5+ 接管 |
| `patch_/seed_` | 2 个 | 连接器一次性补丁（20260908/20260809），已被 `build_connectors_*` 与 `enrich_provenance` 覆盖 |
| `recover_*` | 2 个 | 特定字段/单实体恢复（XFA017 等），非通用工具 |
| `upgrade_*_mi_202609XX` | 3 个 | 2026-09 三批 MI（机械接口）升级批次，属于一次性数据迁移 |

**为什么这些不是活跃资产**：
- **日期化**：文件名带 `202608XX`/`202609XX`，语义上是"这一次批次"，不是"持续工具"。
- **有上游替代**：对应的长期治理脚本（`govern_*`、`enrich_*`、`build_*`）仍在 `scripts/`。
- **不被任何入口引用**：全仓 `grep` 确认无 CI/部署/回归流程引用它们。

**恢复指引**：如某脚本被误归档但仍需运行，`git mv scripts/_archive/<file> scripts/` 即可，
或直接在原地 `python scripts/_archive/<file>` 执行（脚本内部路径引用父目录根，不受位置影响）。

**边界（诚实说明）**：
- 本目录**不参与 `npm run ci` / `scripts/ci_gate.py`**（CI 只扫主 scripts/）。
- 本目录**不参与 `scripts/regression.py` 的 L1.x 检查**（回归只针对活跃代码路径）。
- 因此本目录内文件损坏**不会**触发 CI 告警——这是有意的"冷冻"，避免历史批次干扰活跃开发。
