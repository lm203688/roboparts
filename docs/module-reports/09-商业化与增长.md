## 一、板块定位与边界

**一句话**：把「判定能力」变成可持续的收入与增长——但**明确拒绝抽佣**（一旦抽佣，判定就不再中立）。

**三条子链路**：

| 子链路 | 资产 | 实测状态 |
|---|---|---|
| **付费（积分制）** | 虎皮椒支付（`api.xunhupay.com`）+ Creem；套餐 starter ¥9/100 分、pro ¥29/500 分、lifetime ¥199/无限 | ⚠️ **链路完整，零真实付费** |
| **积分账本** | `_lib/ledger.js`（唯一入口）+ `/api/credits/*` | ⚠️ **曾静默失效**（见下） |
| **增长** | 22 篇技术文库 + KPI 日报 + 社交自动发稿 + GEO/MCP 健康仪表盘 + 候补页 | ⚠️ **内容产能强，转化弱** |

**实测关键事实（重要）**：
- `wrangler.toml` 绑定 5 个 KV：`USER_CREDITS` / `API_KEYS` / `SUPPLIERS` / `SUPPLIER_INQUIRIES` / `URDF_LIBRARY`。
- **`USER_CREDIT_HISTORY` 从未绑定**——而账本代码曾依赖它。`ledger.js` 文件头如实记录：注册赠送 100 积分、真实付款到账、历史查询**全部静默不写**，把「账本从没记过」渲染成「你没有交易」。**「在钱上撒谎」**。
- 现已修复：账本回落至 `USER_CREDITS` 的 `hist:` 前缀，且立下两条硬规矩：**「不可读 ≠ 空」**、**「不可读时汇总必须是 null 不能是 0」**。

## 二、流程审计

### 2.1 流程是否合理

| 环节 | 是否合理 | 实测证据 |
|---|---|---|
| 商业模式选择 | ✅ **极合理** | 「不抽佣」——「一旦抽佣，判定就不再中立」。这与整个项目的定位自洽 |
| 积分制定价 | ✅ 合理 | 1 积分 = 1 次调用，永久有效无月费；三档（¥9 / ¥29 / ¥199）覆盖试用到重度 |
| 账本唯一入口 | ✅ 强 | 把 4 处各自 `if (env.USER_CREDIT_HISTORY)` 收敛为 `ledger.js` |
| 账本诚实纪律 | ✅ **极强** | 「不可读 ≠ 空」；汇总 null 不给 0；同 `compat_engine` 的 `overall=null` 纪律 |
| 付费墙字段清单 | ✅ 强 | `paywall.js` 单一真相源（10 个高价值字段黑名单） |
| 测试订单隔离 | ✅ 合理 | 与 `creem.js` / `notify.js` 保持同步 |
| **增长链路** | ⚠️ **内容多转化少** | 22 篇文章 + 自动发稿，但 `demand-signal` 为 0 |
| **真实付费** | ❌ **零** | 无任何真实交易记录 |

> **判断**：**商业模式的「克制」是正确且罕见的**（不抽佣、不卖零件、不导向自家产品），**账本的诚实纪律也极强**。但**零真实交易**说明这一切还只是「设计」。

> **结论**：**商业链路逻辑完整且诚实，但零真实发生**。这是全仓「完成度最高但最空」的板块。

### 2.3 是否符合人类使用习惯

| 用户 | 真实诉求 | 本板块支持 | 契合度 |
|---|---|---|---|
| 免费用户 | 「先试试值不值」 | 免费层有额度（BOM ≤ 12 项），但**选型引擎无免费试用** | ⚠️ |
| 付费用户 | 「一次付清，别月费」 | ✅ 积分制永久有效 | ✅ 好 |
| 付费用户 | 「我知道我花了多少」 | ✅ 账本历史 | ✅ 好（已修） |
| 中国用户 | 「能用微信/支付宝吗」 | 虎皮椒（聚合支付） | ✅ 好 |
| 海外用户 | 「能用信用卡吗」 | Creem | ✅ 好 |

> **关键缺口**：**「免费试用」不足**。选型引擎 2 积分/次，无试用；BOM 免费但有 12 项上限。**用户在没有体验过价值之前就被要求付费**——这是转化率的最大阻碍。

## 三、市场竞品与市场需求比较

### 3.1 竞品对照

| 竞品 | 商业模式 | RoboParts 的差异 |
|---|---|---|
| **TraceParts / GrabCAD** | 厂商付费上架 + 广告 | RoboParts **不抽佣、不卖零件**，靠 API 订阅 |
| **Octopart** | 广告 + 导流分成 | RoboParts 明确拒绝导流分成（保中立） |
| **数据 API 商**（如各类工业数据） | 订阅制 | RoboParts 定价极低（¥9 起），更像「象征性收费」 |
| **开源项目 + Sponsors** | 赞助 | RoboParts 已有 GitHub Sponsors / OpenCollective 文案 |

> **生态位**：RoboParts 的商业定位是「**中立判定能力的 API 订阅**」——不卖货、不抽佣、不导流。**这个定位的难点是：中立性有价值，但「谁为中立性付费」不清楚。**

### 3.2 市场需求实测

- **零真实付费**、**零真实注册证据**。
- `negative-results.md` 中与本板块相关的负结果：
  - **NR-06「竞品 npm 下载量作为己方指标」= 指标污染，已纠正**。
  - **NR-07「中文 SERP 外链建设」= 降级**。
  - **NR-08「ROS Discourse 投稿（自动化）」= 阻塞**（「发帖响应层保持人工闸门，永不自动化」）。
- `demand-signal.json`：全 0。

> **判断**：**增长板块是全仓「投入产出比最差」的板块**——22 篇文章 + 自动发稿 + GEO 仪表盘，换来的是 0 真实需求信号。**内容产能 ≠ 需求**。
