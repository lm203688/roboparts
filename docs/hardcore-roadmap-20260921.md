# RoboParts 硬骨头路线图（20260921）

> 起因：`docs/phase2-plan-20260921.md` §5.3 有一张「不做」清单（X1–X8）。
> 本文件按「项目要产品化、完整化」这个新前提，把那张清单**逐条重估**，
> 把真正"别人不做、且只有我们能做"的重新提上日程。
>
> 重估用的三条判据（缺一不可）：
>
> 1. **无人占位**：TraceParts / Octopart / Tnkr / Allonic 都不做这件事（要么做不了，要么不愿做）。
> 2. **我们已有半成品**：不是从零造，而是把已有资产做成闭环——否则是空想。
> 3. **失败可判定**：能写出机械校验的验收条件。做不到这一条的，就不是"硬骨头"，是"愿景"。

## 一、重估结论总表

| # | 原判 | 重估 | 一句话理由 |
|---|---|---|---|
| X1 | 不做：造脑 / 造芯片 | **维持不做** | 但补一句边界：我们不造脑，**我们定义脑×体的接口契约**（见 `neurorobotics/`） |
| X2 | 不做：VLA 模型部署 | **维持不做**（范围收窄更明确） | 部署 VLA 是 Tnkr 领地 + 算力黑洞；但 **VLA↔硬件 的信号契约**是无人区，归入 H4 |
| X3 | 不做：整机构建 / 皮肤系统 | **维持不做** | 造整机不是我们的活；但 **整机级的可装性图**（多个零件能否组成一条可用链）是我们的活 |
| X4 | 不做：Marketplace | **改判：做**，但降级为「来源引用层」 | 见 H2。不做佣金中介（X5 仍不做），做"判完之后去哪买"的可核验引用 |
| X5 | 不做：佣金中介 | **维持不做** | 立场即卖点：一旦抽佣，判定就不中立了 |
| X6 | 不做：开源 BOM 反喂 ingestion | **改判：做**，但换实现路径 | 见 H1。旧方案（`oss_components.json` 直接反喂）确实做不到位；新路径是**缺口清单驱动的双向贡献闭环** |
| X7 | 不做：Tnkr 官方 parts supplier 提案 | **维持不做**，改为被动 | 通道非对称的判断仍成立。等覆盖率上去了，让他们来找我们 |
| X8 | 不做：GitHub star 竞赛 | **维持不做** | 用户量小、单点价值高，拼 star 是错配 |

净结果：**8 条里 2 条改判为做（X4、X6），1 条范围收窄（X2），5 条维持不做。**
改判的两条，加上原本就在做的两块，构成下面的四块硬骨头。

## 二、四块硬骨头

### H1 · 机械接口声明率：5.75% → 30%+（数据护城河）

**现状（现算，勿手写）**

| 指标 | 值 |
|---|---|
| 总实体 | 798 |
| 机械接口**适用**（需声明） | 435 |
| 其中 `not_declared`（答不出来） | 410 |
| 已声明（full 15 + partial 10） | 25 |
| **声明率** | **5.75%** |
| `n_a`（不适用，如软件实体） | 363 |
| 跨厂商可直接横向比较的 A 级条目 | **0** |

**为什么是硬骨头**：94.25% 的适用条目答不出"能不能拧到一起"。这不是技术难题，
是**苦力活**——要一条条读厂商 datasheet、抠出法兰标号与孔位。
TraceParts 不做（他们只做目录），Octopart 不做（只做电气采购），Tnkr 不做（只做整机 BOM）。
**没人愿意做的原因正是它的护城河价值：谁做了，谁就有全网唯一一份可核验的接口事实表。**

**已有半成品**：`/api/spec_declare`（规格书文本 → ISO 9409-1 结构化提取，确定性规则+出处）、
`CONTRIBUTING.md`（声明通道）、`.github/ISSUE_TEMPLATE`（出处字段强制必填）。
**闭环缺的是**：从"能提一条"到"批量补一类"的流水线。

**路径**：
1. 按品类分批，先啃谐波减速器（原 P0-2）——它的法兰标号最规范、最易机器抽取。
2. 每条声明必须带 `source_url`，且主机名落在 `MECH_SOURCE_HOSTS` 白名单内（厂商官域）。
   第三方实读出处降级写进 `source` 文本留痕。
3. 声明进 `api/entities.json` 后，由 `onboarding_block.facts()` 现算——**禁止在页面手写声明率**。

**验收（机械可判）**：
- `python scripts/onboarding_block.py` 输出的 `mech_pct` 单调不降（棘轮）。
- 每新增声明都必须能在 `source_url` 上 200 可达（离线校验：主机名 ∈ 白名单）。
- `python scripts/ci_gate.py` 全绿（声明不破坏 schema / mount_type / 分发一致性）。

### H2 · 判完之后的闭环：来源引用层（sourcing reference）

**为什么是硬骨头**：RoboParts 现在的价值止于「**能不能装**」。
判完"不兼容，需转接盘"之后，用户下一步是"**转接盘去哪买 / 找谁加工**"——
这一段全网无人做中立版本：TraceParts 有供应商但只在自己目录内，
Octopart 只做电气件，加工平台（如 Xometry）只做来图加工**不懂接口语义**。

**关键立场（与 X5 不做的边界）**：
- **不做**：佣金、返点、撮合抽成、付费排序。一旦抽佣，判定就不再中立，核心卖点崩塌。
- **做**：**不抽佣的来源引用**——对每个判定结果，给出可核验的加工路径引用
  （如"本转接盘几何参数已给出，可交任意 3D 打印/CNC 服务"），并**标注我们不参与交易**。

**已有半成品**：`adapters/gen_adapter.py` + `adapter-generator.html`（参数化生成转接盘几何，
可导出 OpenSCAD/STL）。**闭环缺的是**：从"生成了几何"到"给出了可核验的加工去向"这一步。

**验收（机械可判）**：
- 转接件三方几何一致性闸门（本轮已建，`scripts/check_adapter_geometry.py`，含 7 例阴阳自证）持续绿。
- 页面上不得出现任何"佣金/返点/付费排序"字样（grep 判据）。
- 来源引用必须显式声明"RoboParts 不参与该笔交易"。

### H3 · 转接件几何的"可打印可信"（工程交付级）

**为什么是硬骨头**：兼容性平台里 **没有第二家**会把转接盘真的生成出来给你。
因为它要求同时握住"标准梯级表"和"厂商偏离值"，还要保证预览与产物是同一套几何。

**已有半成品**：三方实现（three.js 预览 / OpenSCAD 导出 / CadQuery CLI）+ 9 档预设。
**本轮已做的地基**：
- 修掉 `gen_adapter.py` 里那条**过期警告**（它说预览分支把 pinPCD 当半径用——
  实测早已修对，留着会误导下一个维护者"修"回去）。
- 新建 `scripts/check_adapter_geometry.py`：把"三处必须一致"变成机械可判定的，已挂进 CI。
  **它自己也被阴阳自证过一次**：第一版判据只扫全文件的 `pinPCD/2*`，
  而预览分支有 `cos` 与 `sin` 两处——只坏一处时闸门照常通过（假绿）。
  现在判据要求 `s.pinPCD/2` 对 **cos 与 sin 都成立**，并把"只坏一半"列为阴性对照。

**闭环缺的是**：把"生成的几何能用"往前推一步——几何自交/最小壁厚/螺栓头干涉检查。

**验收**：几何闸门常绿；新增的干涉检查必须有阴性对照（喂一组真会干涉的参数，必须判红）。

---

### H4 · 机械兼容之外的接口契约（电气轴 + 信号轴）

**为什么是硬骨头**：整个行业只会说"接口兼容"，但**"接口"其实是三层**：
机械（能不能拧上）、电气（电压/协议是否匹配）、信号（控制语义是否对齐）。
99% 的平台只做第一层，或把三层混成一个模糊的"兼容"。
**把三层拆开、并诚实标注每层的未知**，是 RoboParts「三态诚实判定」的自然延伸。

**已有半成品**：
- `api/electrical_interfaces.json`（电气轴，已上线 + 免责「协议兼容 ≠ 电气兼容」）
- `neurorobotics/signal_interface.schema.json`（信号契约层，针对神经机器人 GAP-G2）
- `api/negative_compat.json`（81 条裁决：9 identity / 0 direct / 72 adapter_required）

**闭环缺的是**：三层之间的**级联判定**——"机械兼容 + 电气兼容 + 信号兼容"才算真兼容，
任一层未知就必须输出"无法判定"而不是"兼容"。

**验收**：级联判定的任一单层为 `null`（未知）时，总结果必须是 `null`，不得 fail-open 成 `true`。
必须带阴阳自证：构造"机械 true / 电气 unknown"的组合，断言总结果不是 true。

## 四、诚实边界（这些现在**还做不到**，不要当成已完成）

- **H1 的 30% 是目标不是现状**。当前 5.75%，补数据是长期苦力活，依赖厂商 datasheet 可得性。
- **H2 只是"引用层"，不是市场**。没有供给侧的实时库存/报价，也不打算做——那需要抽佣，与 X5 冲突。
- **H3 的几何闸门只保证"三处一致 + 标号自洽"**，**不保证"一定能装上"**——
  真正的装配可行性还需要公差链与材料强度，当前数据集没有这些字段。
- **H4 的电气轴覆盖率极低**：actuators 的 connector 声明 4/220 ≈ 1.8%，其余不臆造。
- **A 级可比条目为 0**：目前没有任何跨厂商可直接横向比较的条目，
  所有对外表述都必须保留这个前提，不得暗示"可直接比价"。
