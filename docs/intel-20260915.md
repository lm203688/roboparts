## 3. MINERVA — 基准 / 研究情报（小模型容量地板）

**一手来源**：`github.com/k1000dai/MINERVA`（Apache 2.0）；arXiv 2609.03715（2026-09）；HuggingFace `k1000dai/MINERVA`；humanoidintel.ai 解读。

**已核实事实**：
- MINERVA = **MIN**imal **E**fficient **R**obotic **V**ision-**A**ction policy，0.54M 参数紧凑操作策略，面向 LIBERO 40-task 闭环基准。
- 结果：4 套件平均 **95.75%**（L1 head），仅比 π0.5（4.1B）低 2.4 点，用 **7,700× 更少参数**；笔记本 CPU **5–9 ms/chunk**，无需 GPU。
- 容量地板：~1M 饱和，<0.25M 崩溃。
- 局限：task-ID 条件，**非通用 VLA**，不能执行未见指令；LIBERO-Plus 扰动降到 **46–56%**（光度鲁棒 ≈0）。
- 关键发现：LIBERO 指令条件主要选「记忆任务」（task-ID 置换探针降到近随机）→ 基准记忆动态；flow matching 相对 L1 回归无 detectable 优势。

**RoboParts 关联**：
- 支撑 RoboParts「零件级判定可用小模型」叙事：有界操作任务 0.54M 即够，呼应 RoboParts 轻量 Copilot 路线。
- LIBERO 饱和 + 鲁棒性差 → 研究空白信号（与 SwarmLabs 科研实体「研究空白」同源，但本次归 RoboParts 作基准情报）。

## 5. P0 审计：机械声明率为何「补不动」（2026-09-15）

**用户指令**：「真实 BOM 机械接口声明贡献（P0 验收硬缺口 — 数据缺口，非代码 bug）这个需要你想办法解决了」

**结论：该缺口被误诊为「纯数据缺口」。真实情况是三层叠加，前两层是代码缺陷。**

### 5.1 唯一在动这个数字的两条通道：一条在编造、一条在放行

| 通道 | 缺陷 | 处置 |
|---|---|---|
| `scripts/urdf_auto_extractor.py` | `classify_flange_type()` 仅凭「revolute 关节数 ≥ 5」返回 `ISO 9409-1-50-4-M6`，随后按 `"ISO" in flange` 标 `declared`。URDF 里根本没有法兰事实——**连它自己管道的 `build_flywheel_layer.mjs` 开篇都写着「URDF 不含机械接口事实，故 mechanical_interface 一律留空（不编造）」** | 重写：删掉一切推断，只留真实 URDF 事实 |
| `scripts/bom_backfill.py` | `SOURCES` 硬编码 (名称→法兰) 对；`source_url` 塞**公司名** `'Universal Robots'`（非 URL）；evidence 只写 `"... official documentation"`（无深链）；全部照标 `declared` | 重写：只判结构、不判证据、不产出声明 |
| `scripts/build_flywheel_layer.mjs` `fromBom()` | 采信门槛只有 `if (!b.source_url)`——**非 URL 字符串照样放行**为 `declared / confidence: medium`。这是 L1.78 在贡献层的 **fail-open 镜像** | 改为走共享判据（fail-closed） |

即：**唯一能把 P0 数字抬起来的东西，是一台制造该数字的机器。**

### 5.2 提交通道从来没通过

`build_flywheel_layer.mjs` 读 `bom.components || bom.entities`，而提交入口与 `bom_backfill.py` 写的键是 **`entries`** → schema 不匹配，通道静默无效（此前靠「跑不通」侥幸挡住了伪造数据）。已修，并用 4 条合成提交做端到端探针：**5/5 通过**（含「非 URL 出处」「非白名单域名」「表外 ISO 编码」三类必拒 + 合规项必放行）。

### 5.7 本轮新增的两条一手否证（把可采面压得更准）

1. **`platforms` 不是富矿（推翻我自己的假设）**：库内 30 条未声明的 `platforms` 全是**人形机器人**（Tesla Optimus Gen3、Figure 02/03、Unitree G1/H1、Boston Dynamics Atlas、Agility Digit、Apptronik Apollo、1X NEO、Fourier GR-1/GR-2、UBTech Walker S、Xiaomi CyberOne…）。人形本体**不持 ISO 9409-1 腕法兰**，其腕部是自研接口。⇒ 「机器人厂商文档最全所以最可采」的判断对**工业协作臂**成立，对**人形**不成立。

### 5.8 结论（给决策用）

P0 的数字在**外部证据到位前不应变动**。本轮交付的是**可信度**：把「被造假通道推着走、七套数字互相矛盾、闸门还会静默截断」的现场，变成「单一契约 + fail-closed + 会跑到底的门禁 + 一个真正能用且不会收垃圾的贡献入口」。真实抬升只差**逐型号官域出处**这一项输入。
