# 开源平台扫描与借鉴研发报告 · 2026-09-07

> 任务：扫描开源平台，识别对我们平台（RoboParts，仿生机器人零部件兼容平台）**互补或提升**的项目，
> 并把可借鉴的能力**研发落地**。本报告是扫描结论 + 落地清单，所有数字均现算，未用记忆值。

## 一、扫描范围与判定框架

按「拿来用 / 做衔接 / 成为生态一环」三档分类（不笼统说"有参考价值"）：

- **拿来用**：能力直接补我们缺口，可摄取/接入， zero-to-low 改造。
- **做衔接**：范式/标准可借鉴升级我们现有模块，需二期工程。
- **成为生态一环**：对方是平台/社区，可让我们的数据/工具成为其生态的一部分（或反之）。

## 二、扫描结果

| 项目 | 协议/性质 | 与我们关系 | 判定 | 落点 |
|------|-----------|------------|------|------|
| **step.parts** | MIT，16,847 条带标准号 STEP 零件（Vercel 托管，开放 API） | 直接互补：我们有 81 条法兰裁决但缺「用哪颗螺栓」与真实几何资产 | **拿来用** | 摄取 + 转接盘 BOM 物料清单 |
| **atopile** | 约束驱动电子设计（constraint → artifact） | 范式升级我们的 adapter 生成器（"约束即产物"） | **做衔接**（二期） | 范式启发 |
| **CadQuery / build123d** | 参数化 CAD（Python，OCCT 内核） | 提升：既有 `adapters/gen_adapter.py` 的几何内核 | **提升** | 已装 build123d |
| **Open Know-How (OKH) manifest** | 开放硬件元数据标准 | 做衔接：可采纳为零件 schema 的兼容层 | **做衔接**（二期） | 评估 |
| **机器人 MCP server（市面）** | 多为控制型（运动/感知） | 非竞争：无兼容数据层对手，确认差异化护城河 | 无动作 | 竞品定位锚 |

### 关键发现

1. **step.parts 的 339 个执行器含 CubeMars(27) / myactuator(18) / LeaderDrive(25) / 达妙(9) / RobStride(9) / SteadyWin(10) / HEBI(12)** —— 全是人形/仿生机器人主流 QDD 执行器，且每条带 **STEP 几何文件**。这给了 P0「411 条机械接口未声明」一条**自动填充路径**：从 STEP 几何程序化抽取安装孔阵列 → 反推 PCD/孔数/孔径。
2. **2,118 条紧固件、37 种标准号，M3/M5/M6/M8/M12/M16（我们 9 档法兰的全部螺纹需求）均有 ISO 标准件可直接引用** —— 裁决库只写「两侧按各自 PCD/孔数/螺纹开孔」，从不说用哪颗螺栓；step.parts 把这一步补上。

## 三、研发落地（本次已交付）

| # | 文件 | 作用 | 证据 |
|---|------|------|------|
| 1 | `scripts/ingest_step_parts.py`（新建） | 白名单摄取 step.parts 全量索引 → `api/step_parts.json` | 现算 **6,220 条**跨 7 品类；9 档法兰螺纹全部命中库存；缩水闸门 >10% 拒写 |
| 2 | `adapters/bolting.py`（新建） | 转接盘螺栓物料清单：给定两侧法兰 + 板厚，从 step.parts 选**真实 ISO 标准件** | A40→A63：ISO 4762 M6×14；A100→A250：M8×35 / M16×45 |
| 3 | `adapters/gen_adapter.py`（增强） | 接入 bolting（`--bom` / `--bolt-inventory`）；补全缺失的 **A63** 预设 | 裁决库 9 档、原生成器仅 8 档 → A63 用户此前无法生成 |
| 4 | `adapter-generator.html`（一致性修复） | 原 A100=6×M10、A160=8×M16 与裁决库（A100=4×M8、A160=4×M12）冲突 → 按真相源对齐并补 A63 | 现 **9/9 档位与 `api/negative_compat.json` 零偏差** |

### 闭环成立示例
A40 → A63 转接盘 = OD87 × 6.3mm，两侧各用 **ISO 4762 M6×14 内六角螺栓**（精确长度由板厚 ≥1.5×穿透算出）。从「判定需要转接」一步走到「可下单物料」。

### 一致性修复的重要性
浏览器版此前与裁决库三处打架（A100/A160 螺纹错 + 缺 A63）。后果是：用户查裁决库得到「A100 需转接」，回生成器却得到一块孔位错误的板 → **判定与产出断链**。现已对齐唯一真相源。

## 五、二期候选（做衔接）

- **atopile 约束范式**：把 adapter 生成从「填参数出几何」升级为「声明约束（承载扭矩/轴向力/间隙）→ 自动反推板厚与螺栓等级」，反向校验我们的裁决。
- **OKH manifest**：把零件 schema 对齐 OKH 标准，使 RoboParts 实体可被开放硬件生态直接消费（"成为生态一环"）。
