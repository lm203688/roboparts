# 判定层做深 vs 延伸物理验证 —— 一次不留模糊的选择

> **性质**：留痕决策文档。目的是把「判断依据、备选方案、最终选择、验证判据」写下来，
> 让下一个版本能查到为什么这样决定，也能推翻它。

> **方法**：只信仓内产物 + 一手 curl 数据，不采信「业界普遍观点」。

## 一、决策点是什么

RoboParts 当前占据流水线上的「判定」环：

```
text-to-cad（生成） → RoboParts（判定：能不能装） → MuJoCo / roboxdb（物理验证：能不能真的动）
                                                        ↓
                                                   训练（GR00T / LeRobot）
```

问题：下游出现直接竞品 roboxdb，用 MuJoCo 补齐了「能不能真的动」这一层。
如果 roboxdb 反向补上「跨厂商接口判定」，RoboParts 的差异化会被夹在两环之间——
上游被生成工具挤压、下游被物理验证挤压。**下一阶段必须做一个不留模糊的选择。**

## 二、备选方案（三选一，不含折中）

| 方案 | 主张 | 3 个月后长什么样 |
|---|---|---|
| **A. 判定层做深** | 保持「静态类型检查器」定位，把三态类型系统做到工业级 | 三态裁决率从 0.1% → 20%+；国标参考实现；GB/ISO 标准共建席位 |
| **B. 延伸物理验证** | 补 MuJoCo/MJCF 桥接，把「几何装得上」升级到「运动学真的能跑」 | 一个能编译 MJCF 的桥接器 + 干涉/可达性检查 |
| **C. 两头都占** | 判定 + 物理验证都做 | 资源分裂，两条都不精，且物理验证与 roboxdb 正面撞车 |

## 三、判据（4 条硬指标）

不靠直觉，靠可测数据：

| 判据 | A 得分 | B 得分 | C 得分 |
|---|---|---|---|
| **1. 与护城河的一致性** | 五维评分引擎、三态语义、国标映射、46 robot_ai_models、21 MCP 工具全是「判定」资产，A 直接加杠杆 | MuJoCo 需要重新学一个技术栈，护城河不叠加 | 双份护城河 = 双份债务 |
| **2. 数据资产复用度**（复用率 = 已有资产能被新目标复用的比例） | ~90%（868 实体、co_mount、cohort_feasibility、evidence_valuation 全部可复用） | ~30%（需要几何 STEP/MJCF 描述，仓库内几何声明率仅 16.2%，且是「法兰孔位」而非「URDF 关节链」） | 一半 90% 一半 30% |
| **3. 竞品重叠度**（越低越好，避免正面撞车） | 与 roboxdb 互补（判定 vs 物理）；与 text-to-cad 互补（判定 vs 生成） | 与 roboxdb 正面重叠（都做物理验证），且其浏览器内 MuJoCo 已上线 | 一半互补一半重叠 |
| **4. 单位成本（人日/能力点）** | 已有 `functions/_lib/compat_engine.js` + `scripts/compose_engine.py` 两套引擎，边际改动成本极低 | 需要引入 MuJoCo Python 绑定（Windows 安装实测失败，见报告 §2.5）、mjx 前端、几何描述层——估计 ≥ 60 人日才能出可发布版本 | 两倍以上 |

**汇总**：A 全票，C 次之，B 最差。

## 四、A 方案下的具体边界（不留模糊）

选 A 不代表「永远不做物理验证」，而是**明确边界、留下接口**：

| 我们**做**（判定层做深） | 我们**不做**（明确边界） | 接口（未来若变主意） |
|---|---|---|
| 静态类型检查（协议/电气/机械/软件四维） | 物理仿真（MuJoCo / PyBullet / Isaac Sim） | 输出结构化契约 JSON，供物理引擎消费 |
| 三态语义（compatible / incompatible / unknown） | 干涉检查（需要几何） | 提供几何描述字段的 schema（但不承诺精度） |
| 国标 / ISO 标准映射 | 动力学可达性 | URDF 语法 lint（已有 /api/urdf/lint）——只查语法，不查物理合理性 |
| 溯源 tier（A/B/C）+ evidence 链 | 训练数据生成 | 数据集走 Croissant + HuggingFace/Zenodo，可被外部消费 |
| Agent 分发面（21 MCP 工具 + GitHub Action） | 浏览器内仿真 | 未来若做，作为独立子域而非主线 |

> **一句话边界**：RoboParts 判「能不能装」，不判「能不能真的动」。
> 需要「真的动」的场景 → 显式指向 MuJoCo / roboxdb，不做黑箱替代。
