> 纪律：**不填假数据凑数**。所有缺口以现算数字登记，配追踪闸门防倒退。

## 一、为什么需要这份登记册

审计报告 16 项缺口中，13 项已通过闸门与代码修复闭环（G-01/03/04/05/07/08/09/10/11/12/15/16 + 新增 7 闸门）。

**剩下 3 项（G-06 / G-13 / G-14）本质是数据侧的真实缺口**——需要人肉查一手 datasheet、跑真机测量、逐条裁决，不能靠脚本伪造。

在本项目"诚实优于好看"的核心定位下，正确处理是：
1. **公开登记缺口**（本文件），让消费方能判断"这条数据在不在缺口清单里"；
2. **建立追踪闸门**（G-T8），保证缺口不悄悄恶化，一旦扩大 CI 立刻红；
3. **明确补齐通道与成本**，把决策权交给责任人。

不登记 = 假装没问题；填假数据凑齐 = 违反核心定位。**登记 + 追踪**是唯一诚实做法。

## 二、三个缺口的当前状态

### G-06 · 机械接口可判定率 6.6%（57/868）

**双口径披露**（README 顶部已同步）：

| 指标 | 分子 | 分母 | 值 | 含义 |
|---|---|---|---|---|
| 声明率（declared_any） | 81 | 500（applicable） | 16.2% | 有"任何线索"（declared + partial） |
| 可判定率（strict decidable） | 57 | 868（total） | 6.57% | `standard` + `flange` 同时非空，真能做法兰装配判定 |

**结构畸形**（现算）：

| 品类 | 可判定 / 该品类总数 |
|---|---|
| platforms | **55 / 106** |
| bionic_mechanisms | 1 / 17 |
| grippers | 1 / 26 |
| **actuators** | **0 / 222** ← 组合判定主战场，全空 |
| 其他所有品类 | 0 / 各品类 |

**根因**：组合判定（G-02 的 composed=0）的输入侧根因。57 条里 55 条是整机平台，执行器↕减速器↕法兰这条组合主战场几乎全空。

**补齐通道**（按 ROI 排序）：
1. **ISO 9409-1 查表**（最省）：M12/M16/M20/30/40/50/60 六轴接口可直接查，无需厂商 datasheet；预估可覆盖 40-60 条 actuators
2. **厂商 datasheet**（中等成本）：Kinematics / Unitree / 1X / AgiBot 等开源人形机器人手册可查
3. **用户贡献**（长期）：spec-declare.html 表单，走 ISO 9409-1 抽取管线

**责任人**：数据层 owner；预估工时 3-4 周（ISO 查表 1 周 + 厂商 datasheet 2 周 + 贡献流程 1 周）

**当前不做的理由**：本轮审计是"找漏"性质，数据补齐是独立工程。见 `DIRECTION_ANCHOR.md` Phase C。

### G-13 · 协议性能基准覆盖率 57.8%（37/64）

**现算**：64 条 `protocols` 实体中，含 `latency` / `jitter` / `bandwidth` / `real_time_perf` 结构化字段的 37 条，缺 27 条。

**README §2 Core Goal 3 承诺**："EtherCAT/CANopen/ROS2/MQTT 协议栈对比、**实时性能基准**、跨协议桥接"。

**缺口清单**（27 条无性能数据）：主要是 ROS 2 DDS 变种、工业总线变体、部分物联网协议。

**补齐通道**：
1. **协议官方 spec**（免费、最省）：大部分协议 spec 自带推荐/最小延迟数值
2. **实测**（成本高）：需要真机 + 抓包工具，是独立工程
3. **诚实标注**（本轮做法）：在 entity 上标注 `performance_evidence_gap: true`，让消费方知道这条数据不完整

**责任人**：待指派；预估 2-3 周

**当前不做的理由**：README 承诺里"实时性能基准"这一项当前覆盖 57.8%，是"部分实现"，不是"完全没做"。登记并追踪，不做则不做；做了则闸门会看到覆盖率上升。

### G-14 · 组件 `n_a` 标注复核（159 条待复核）

**现算**：`mechanical_interface.status == 'n_a'` 且不属于非实体品类（software/specification/market_intelligence/organization）的条目数。

**审计报告结论**：
- `software`(81) / `specification`(101) / `market_intelligence`(17) / `organization`(10) 共 209 条标 `n_a`——**正确**（本就不该有机械接口）
- `component`(659) 里 159 条标 `n_a`——**需要复核**：实物零件标"不适用机械接口"要有解释

**现算分类**（159 条 component 的 n_a 分布）：

| 品类 | n_a 数 | 是否合理 |
|---|---|---|
| chips | 108 | 部分合理（AI 芯片无机械接口）；部分需复核（MCU/FPGA 是模块） |
| interfaces | 44 | 大部分合理（标准文本本身无接口） |
| platforms | 14 | **不合理**（整机平台必有机械接口，应转 declared 或 partial） |
| actuators | 2 | 需逐条复核 |
| grippers | 2 | 需逐条复核 |
| 其他 | -11（负数意味着部分品类 n_a 已低于原估计，因归类漂移） |

**关键子集**：14 条 platforms 标 n_a 是**明确的错误**，应转 declared 或至少 partial。

**补齐通道**：
1. **手工复核**（低成本）：159 条逐条看，14 条 platforms 优先
2. **规则升级**：给 `build_mechanical_interface.py` 加"platforms 品类默认 partial"

**责任人**：数据层 owner；预估 1-2 周

**当前不做的理由**：159 条 n_a 大部分是"合理但不精确"（chips/interfaces 是灰区），真正错的只有 14 条 platforms。登记追踪，不做大动作以免引入新错误。

## 三、追踪闸门（G-T8）

新增闸门 `test_data_gaps_ratchet`：
- 记录三个缺口的当前值（57 / 27 / 159）作为基线
- 每次 CI 现算对比
- **棘轮**：只允许下降（缺口收窄），不允许上升
- 例外：如果上升是"新增实体带入"，须在本文件同步更新基线并写明理由

**设计原则**：闸门不阻止"缺口存在"（那是诚实），但阻止"缺口恶化"（那是失职）。
