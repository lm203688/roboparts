# Verification Antipatterns 2026 — 验证反模式档案

> **性质**：≥10 条事故 → 规则 → 阴性测试。每条反模式必须带：事故描述、根因、规则、阴性测试。
> 
> **来源**：2026-09-23 至 2026-10-16 的真实事故复盘。

---

## AP-001: 自欺型闸门

| 字段 | 值 |
|---|---|
| 事故 | 一致性守卫 + 自称状态 = 自欺型闸门 |
| 根因 | 判据不许信产物自我声明——必须现算 |
| 规则 | 闸门必须验证**实际值**，不验证**声称值** |
| 阴性测试 | 故意改产物声称值（如 composed=0→100），闸门必须判红 |

## AP-002: 子串包含跨语义边界

| 字段 | 值 |
|---|---|
| 事故 | 判据用子串包含（`"composed" in text`）命中跨语义边界 |
| 根因 | 文本子串匹配无类型安全——"composed" 在 "composed of" 里也命中 |
| 规则 | 判据必须用**结构化字段**，不用文本子串 |
| 阴性测试 | 故意在文档里写 "composed of three parts"，判据不能把它算成 composed 对 |

## AP-003: 只查取值域不查自洽

| 字段 | 值 |
|---|---|
| 事故 | 闸门只查 "verdict 在 {composed, type_error, unknown}" 合法值，漏了"换合法值冒充语义" |
| 根因 | 合法值 ≠ 语义正确——`unknown` 可以合法但语义上应该是 `composed` |
| 规则 | 闸门必须查**跨字段自洽**（如 verdict + 缺失接口列表一致） |
| 阴性测试 | 故意把 verdict 从 `composed` 改成 `unknown` 但不改缺失列表，闸门必须判红 |

## AP-004: 一致性守卫不查"不匹配"

| 字段 | 值 |
|---|---|
| 事故 | 数字保鲜守卫只查"有变动就更新"，不查"没变动但声称有变动" |
| 根因 | 单向守卫有盲区——只拦"该改没改"，不拦"不该改乱改" |
| 规则 | 守卫必须双向：有变动→必须更新；无变动→不得更新 |
| 阴性测试 | 故意在没变动的文件里改一个数字，守卫必须判红 |

## AP-005: 变异体构造阻塞 CI

| 字段 | 值 |
|---|---|
| 事故 | 变异评分对全量闸门跑，单次 CI 超时 |
| 根因 | 变异测试是重操作——全量跑会拖慢 CI 到不可接受 |
| 规则 | 只对**核心算子**（compose_core）全量跑变异，其余留夜间 |
| 阴性测试 | 变异评分 CI 必须在 5 分钟内完成 |

## AP-006: 单标量做长期适应度

| 字段 | 值 |
|---|---|
| 事故 | 竞品用 npm 下载量当己方指标——单一标量指标污染前科 |
| 根因 | 单一标量无法反映多维权衡——刷一个指标会牺牲其他 |
| 规则 | 长期适应度必须**多目标**呈现，不得只用一个标量 |
| 阴性测试 | fitness.py 必须返回 3 个独立目标，不得合并成单一分数做长期度量 |

## AP-007: 自动变更修改锚点判据

| 字段 | 值 |
|---|---|
| 事故 | 自进化循环修改 PROJECT_DIRECTIONS_V2.md 的判据定义 |
| 根因 | 锚点是宪法——自进化不能改宪法，否则"变好"失去定义 |
| 规则 | 自进化红线：不得修改锚点判据定义 |
| 阴性测试 | 自进化循环必须检查：修改了 PROJECT_DIRECTIONS_V2.md 则判红 |

## AP-008: Workflow 绕过 fail-closed

| 字段 | 值 |
|---|---|
| 事故 | plan_assembly 工具直接写判定逻辑，绕过 compose_core |
| 根因 | 新工具必须复用同一 core——不得另写判定逻辑 |
| 规则 | 所有新工具必须 import compose_core，不得内联判定 |
| 阴性测试 | plan_assembly 的判定结果必须与 compose_core 直接调用一致 |

## AP-009: 双引擎口径混用

| 字段 | 值 |
|---|---|
| 事故 | Agent 读到"四维 vs 三轴"两套维度时困惑，自行合并 |
| 根因 | 两套引擎口径不同，合并会让 agent 误以为"协议 + signal 是一维" |
| 规则 | 桥接只做维度名映射与场景路由，**不合并两套引擎** |
| 阴性测试 | 桥接产物的 dimension_map 不得把 protocol 映射到 signal |

## AP-010: ISO 映射无原文

| 字段 | 值 |
|---|---|
| 事故 | ISO 22166-1 无原文时硬做映射，失准 |
| 根因 | 无原文的映射是推测，不是符合性 |
| 规则 | 无原文 ⇒ 只做方向性映射，显式声明不构成符合性 |
| 阴性测试 | ISO 映射产物必须有 `honest_limits` 字段声明边界 |
