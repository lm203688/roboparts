## 二、市场定位（一手核实）

### 2.1 象限图（2026-09 实测）

| 象限 | 玩家 | RoboParts 位置 |
|---|---|---|
| **零件数据库**（广度） | Octopart / TraceParts / DigiKey | ❌ 不在（RoboParts 只做机器人零件子集） |
| **零件制造**（硬件） | Allonic（$7.2M pre-seed, 3D Tissue Braiding） | ❌ 已退出（2026-02 转向） |
| **整机平台**（软件+硬件） | Tnkr（Leonardo AI + 4 支柱） | ❌ 不做（互补非竞争） |
| **URDF 结构校验** | RoboInfra（2026-05）/ urdf_validator（MIT）/ UrdfArchitect（BOM 导出） | ⚠️ **相邻挤压**（URDF 侧校验 vs 物理接口侧判定） |
| **物理接口判定**（ISO 9409-1） | industrialroboticshub.com（教学向，50/339） | ✅ **独占**（唯一开放源） |
| **MCP 生态** | xiaozhi-esp32（24.9k★）/ DimOS（1.7k）/ ROS MCP（1.1k） | ⚠️ 0★，未入头部榜 |

### 2.2 真实位置一句话

> **RoboParts 是 ISO 9409-1 物理接口兼容性判定的唯一开放源，正被 URDF 工具群（RoboInfra / urdf_validator / UrdfArchitect）从相邻象限挤压，社区信号为 0，产品扎实但从未进入任何开源传播渠道。**

### 2.3 竞品一手核实（2026-09 状态，非记忆）

- **Allonic**：2026-02-10 融资 $7.2M pre-seed（匈牙利史上最大），转向 3D Tissue Braiding 制造，**已不是竞品**。
- **Tnkr**：推出 Leonardo（AI 硬件工程师），Impact Metrics 全 `0% 0%` 占位；`api.tnkr.ai` 复核仍无 API 面（占位页）⇒ 通道非对称。
- **RoboInfra**（2026-05）：URDF 结构校验 + GitHub Action，**URDF 侧的兼容性校验**，RoboParts 在物理接口侧——**互补但相邻**。
- **urdf_validator**：明确说"LLM 不该算扭矩，需要一个可审计的 oracle 给 agent 调用"——**这正是 RoboParts 的定位哲学**，可互相推荐。
- **UrdfArchitect**：唯一与 RoboParts 有直接功能重叠（BOM 生成 vs BOM 兼容判定），潜在合作。

### 2.4 名字冲突（真实风险）

- Amazon 西班牙站有 Roboparts® 品牌（Cecotec 扫地机配件），SEO 搜索"RoboParts"会混入。
- 另有 `roboparts-premium-bmyr.getsite.online/` 假冒页面。
- ⇒ **品牌名在机器人零部件采购真实商业场景已被占**。SEO 需强制"RoboParts.cc"或"RoboParts 兼容性"全名差异化。

## 三、真实短板（诚实判读）

### 3.1 最大短板：社区信号 0

- GitHub 0 star / 0 issue / 0 PR / 1 contributor（唯一作者，91 commits）
- 9 月 70 commits 全是自我迭代，**没有一个外部交互痕迹**
- LobeHub MCP 目录是唯一非零外部证据，18 天未同步
- **不是"没到时间"，是"从未进入过任何开源传播渠道"**

### 3.2 测量链路本身坏了

- `flushMcp` 读-改-写在多 isolate 下互盖，读数**只证明下界**
- "合并 0/16 分片" ≠ "当天 0 请求"，是**根本没读出来**
- 8/8 前飞轮巡检用裸 curl 打关键路径，未带 selftest 头，历史"404"数据含飞轮自打噪声，无法回溯扣减
- ⇒ **任何"用户在看什么"的分析都是空中楼阁**，直到先修读侧 bug

### 3.3 5.75% 机械声明率是硬阻塞

- applicable 435 / declared+partial 25 / **not_declared 410**
- Tnkr BOM 里 100 个零件对，能判的不到 6 个
- 对外挂"95% 无法判定"的徽章端点，比没有徽章更伤——把"数据不够"变成对方可见的负面证据
- **合法补数据通道只有三条**：厂商 datasheet / ISO 9409-1 查表 / 用户提交带出处
- **"开源 BOM 反喂 ingestion" 已证做不到位**（`ingest_oss_bom.mjs` 写 `oss_components.json`，与声明率分母 `entities.json` 不相通）

### 3.4 象限在被挤压

- URDF 工具群（RoboInfra / urdf_validator / UrdfArchitect）正在做 URDF 侧校验
- 如果 UrdfArchitect 或 RoboInfra 未来加"物理接口"维度，RoboParts 的差异化会被吞掉
- **"零件级+判定象限无人占" 是 2026-08 的旧判断**

### 3.5 变现未验证

- 29 次 API 调用 0 注册（历史实测）
- 支付链路已部署但**无真实转化数据**
- "佣金中介"模式脆弱且不合理（供应商不会主动接入）
- ⇒ **Octopart 模式**（免费搜索 + 数据订阅）更适合当前体量

## 四、下一阶段方向（6 个月）

### 4.1 战略重心转移

**从"数据广度"转向"传播 + 补齐 + 变现"三线并行**。

前 3 个月（09-21 ~ 12-31）的自我迭代已经证明：
- 加 kinematics 层、neurorobotics 层、demand-signal 层 = **自我迭代**，不产生外部交互
- 加 marketplace 设计、modality 蓝图 = **文档膨胀**，不产生用户
- 加闸门、加自测、加漂移收口 = **质量内卷**，不产生传播

下一阶段必须产出**外部可验证的交互痕迹**：第一个 issue、第一个 PR、第一个真实用户、第一个付费转化。

### 4.2 三条主线

#### 主线 A：数据补齐（解 5.75% 硬阻塞）

**目标**：把机械声明率从 5.75% 拉到 **≥20%**（在 1-2 个品类内做到 ≥50%）。

**优先品类**：**actuators（217 条）中的谐波减速器**——ISO 9409-1 A35/A50/A65/A100 四档是公开标准，可批量查表补 `A{n}`。

**通道**（唯一三条合法）：
1. 厂商 datasheet 手动录入（绿的谐波 LCS/LCD/CSG、哈默纳科、来福、同川、杉川——已收录 10+ 家）
2. ISO 9409-1 查表批量补 `A{n}`（脚本化，可自动化）
3. 用户提交带出处（`add_mechanical_interface.py:56` 的 `_curated()` 只保留有 `source_url` 的声明）

**验收**：`mech_pct` 从 5.75% 升到 ≥20%，至少 1 个品类（谐波减速器）达到 ≥50% 可答率。

**成本**：1-2 周纯手工 + 半天查表脚本。

#### 主线 B：传播（破 0 社区信号）

**目标**：拿到**第一个外部交互痕迹**——issue、PR、star、或 LobeHub 用户。

**动作按成本/风险排序**：

1. **给 ToddlerBot 提外链 PR**（零账号风险，验证 Tnkr 侧是否放行外链）——P0，1 天
2. **写 3 篇"三态诚实判定"博客**（英文 + 中文 + ROS Discourse）——P0，3 天。Moltbook 那篇"数据缺失不是失败，是不确定性"的三态哲学在业内没人认真写过，是内容营销的唯一强差异化资产。
3. **发 Onshape FeatureScript MCP 集成文章**（占"CAD→兼容"搜索意图，GEO 收益）——P1，1 天
4. **URDF 工具群合作提案**（给 RoboInfra / urdf_validator / UrdfArchitect 发 issue 或邮件，提议集成 RoboParts API 作为 URDF 侧的物理接口补充）——P1，1 天
5. **修遥测读侧 bug**（P0，0.5 天，最高 ROI——现在连"有多少人访问"都不知道）
6. **LobeHub 目录同步 + Glama 上架**（半天）
7. **README 与 API 计数对齐**（1 小时——GitHub 访客第一印象就是"这项目 6 周没维护"）

**不做什么**：
- 不主动发 Tnkr "parts supplier" 提案（通道非对称，Impact Metrics 全 0%，主动提等于把 5.75% 当筹码递出去）
- 不把 roadmap 建立在 Tnkr 上（平台自身未验证）
- 不拼 GitHub star 数（其他热门 MCP 都解决"如何控制机器人"，RoboParts 解决"如何选型/判定兼容"——用户量小、单点价值高，不适合拼 star）

#### 主线 C：变现（验证商业模型）

**目标**：拿到**第一个真实付费转化**（非测试订单）。

**动作**：
1. **从"佣金中介"转向"数据 API 订阅"**（Octopart 模式）——目标客户是**机器人集成商和 ROS 项目团队**，不是终端买家
2. **Pro 层从"佣金分成"改成"API 数据订阅"**（按调用量），价格锚定 Octopart 的 $200/月起
3. **保留 9 元鉴权**作为"付费意愿探针"（验证用户是否愿意为一笔数据付费），不作为主收入
4. **不追 marketplace**（`ops/marketplace-architecture.md` 已写完但零执行，社区信号 0 阶段做 marketplace 等于空中楼阁——先有用户再有市场）

## 五、功能定位（做什么 / 不做什么）

### 5.1 核心定位（一句话）

> **RoboParts 是跨厂商机器人零部件兼容性判定层——给 URDF 工具群、Tnkr 类整机平台、ROS 项目团队提供"两个零件能不能装到一起"的可审计裁决。**

### 5.2 做什么（P0）

| # | 功能 | 理由 |
|---|---|---|
| F1 | ISO 9409-1 物理接口判定（已具备） | 独占象限，唯一开放源 |
| F2 | 三态诚实判定（`confirmed/unclassified/noise`） | 业内没人认真做，内容营销强差异化 |
| F3 | MCP 工具面（10 工具已上线） | 占"CAD→兼容"搜索意图 |
| F4 | 谐波减速器品类补到 ≥50% 可答率 | 解 5.75% 硬阻塞，是 Tnkr 徽章端点的前置 |
| F5 | 兼容裁决徽章端点（200 行纯静态） | Tnkr BOM 唯一可消费形态（外链 + 一张图） |
| F6 | 遥测读侧修复 | 现在连"有多少人访问"都不知道，谈市场判断都是空的 |

### 5.3 不做（明确排除）

> **20260921 重估**：本清单已按「项目要产品化、完整化」重估一遍，
> 结果另见 [`docs/hardcore-roadmap-20260921.md`](./hardcore-roadmap-20260921.md)。
> 净结果：**X4、X6 改判为做**（降级/换路径），**X2 范围收窄**，X1/X3/X5/X7/X8 维持不做。
> 下表的「重估」列即为结论；理由是上面的三条判据（无人占位 / 已有半成品 / 失败可判定）。

| # | 不做 | 理由 | 重估 |
|---|---|---|---|
| X1 | 造脑 / 造芯片 | Eon/DeepMind/Intel/BrainChip 领地（见 neurorobotics 定位校准） | 维持不做 |
| X2 | VLA 模型部署 | Tnkr 已把 Models 支柱升级为"VLA models optimized for your hardware"，边界更清晰 | 维持不做；**VLA↔硬件信号契约**改归 H4 做 |
| X3 | 整机构建 / 混改 / 皮肤系统 | Tnkr 层位，我们往零件数据走 | 维持不做；**整机级可装性图**属我们 |
| X4 | Marketplace（社区数据市场） | 设计已完但零执行；社区信号 0 阶段做 marketplace = 空中楼阁 | **改判为做**，降级为「来源引用层」，**不抽佣**（见 H2） |
| X5 | 佣金中介模式 | 脆弱且不合理，29 次 API 调用 0 注册；转 Octopart 数据订阅 | 维持不做（抽佣即立场崩塌） |
| X6 | 开源 BOM 反喂 ingestion | 已证做不到位（`oss_components.json` 与声明率分母 `entities.json` 不相通） | **改判为做**，换路径：缺口清单驱动的双向贡献闭环（见 H1） |
| X7 | Tnkr 官方 parts supplier 提案 | 通道非对称，主动提等于把 5.75% 当筹码递出去 | 维持不做，改为**被动等对方来** |
| X8 | GitHub star 竞赛 | 其他热门 MCP 解决"如何控制"，RoboParts 解决"如何选型"——用户量小、单点价值高，不适合拼 star | 维持不做 |

### 5.4 边界哲学（诚实铁律）

- **无出处不收**：宁可留着 `not_declared`，也不猜。
- **未声明即"未知嵌入"，不填 0**：把"厂商没给扭矩"填成 `torque_nm=0`，等于骗策略"这个零件没有重力"，是假绿。
- **`overall_compatible=null` 表示"无法判定"，不是"不兼容"**：训练时按无标签处理，不要当负样本。
- **跨厂商可直接横向比较的 A 级条目为 0 条**：每条数据带 `source_tier`(A/B/C) 与 `confidence`，请据此判断可信度。
