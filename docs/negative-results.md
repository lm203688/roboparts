## NR-01：补 declared 机械电气数据拉 fill_pct 到两位数

**假设**：补录机械接口 declared 数据可使 `fill_pct` 从 0.57% 提升到两位数。

**投入**：8+ 轮飞轮运行（2026-08-05 至 2026-08-12），累计约 80+ 小时。

**实测结果**：
- 机械声明率从 0.57% 提升至 1.40%（L1.74 后）
- 首条尺寸级 declared 落库（ACT-028 Robotiq 2F-85 三值 ISO 9409-1 孔位集合）
- 但 83.6% 组合仍诚实回答"不知道"（null）——这不是数据问题，是行业公开数据本身稀缺

**结论**：**此路不通**。问题不是取证投入不够，而是厂商公开数据在尺寸级（孔位集合/法兰规格）层面根本不存在。ISO 9409-1 定义了命名语法，但厂商不公开具体尺寸数据。

**反哺建议**：
- 停止以"fill_pct 达两位数"为目标——这是一个在行业数据稀缺前提下的不可能目标
- 转向：用 ISO 9409-1 的命名语法（而非尺寸数据）做方向性兼容判定，显式标注"不构成符合性判定"
- 新目标：`fill_pct > 2%` 且每条 declared 有一手出处（厂商手册深链 + 内容哈希）

**关联定理**：T2（关于取证组织方式的负结果）——取证投入与 unknown 削减不成比例时，应转向"更好的 unknown 处理"而非"更多取证"。

## NR-02：给 706 条零件批量打合规标签

**假设**：国标 GB/T 47864-2026《人形机器人模块化通用技术要求》给出可判定 L1/L2 合规分级，批量打标可提升平台可信度。

**投入**：2 轮情报调研（2026-08-06 至 2026-08-07），约 4 小时。

**实测结果**：
- 判据覆盖率核算：`voltage` 11%（含 48V 仅 2%）、`CAN` 8%、`EtherCAT` 5%、热参数 3%、功能安全 0.3%
- 此时发合规标签 = 把没数据渲染成不合规
- 与 L1.22（无价格冒充在预算内）同源——**fail-closed on unknown**

**结论**：**否决**。覆盖率 0.3%~11% 的判据打合规标签是"把没数据渲染成不合规"，与 L1.22 假绿镜像。

**反哺建议**：
- 合规标签必须等判据覆盖率 > 80% 才发
- 当前阶段仅做"方向性映射"（ISO 22166-1 锚点），显式声明"不构成符合性判定"
- 新目标：补 declared 数据至覆盖率 > 80%，然后批量打标

**关联定理**：T1（三态不变量）——覆盖率不足时，三态判定必须保持 `null`，不得坍缩为 `false`。

## NR-03：MCP 端点获客（被点开而非曝光）

**假设**：MCP 端点上线 + 官方 Registry 收录即可带来真实 Agent 接入。

**投入**：6+ 轮飞轮运行（2026-08-06 至 2026-08-08），累计约 60 小时。

**实测结果**：
- `/mcp` 端点访问量 781 次（2026-08-07）
- 官方 MCP Registry active/isLatest（域名所有权得来不可冒名）
- Glama 被动收录（从未提交，Registry 下游自动抓取）
- 但业务调用仅 10 次（search_components 8 / check 1 / recommend 1），归因全为 `script` 模糊 UA
- 真实需求区间 [0, 10]，下界 0

**结论**：**部分未达成**。曝光问题已解决（Registry + Glama 双收录），但"被点开"之后的接入路径仍有断裂：
1. 文档指向未发布 npm 包（AP-05）
2. 缺参与真不存在 ID 返回同一形状（L1.24）
3. 技能契约 5 个工具实跑 0 可用（AP-07）

**反哺建议**：
- 曝光不是瓶颈，"接不进来"才是
- 优先修接入路径（AP-05）和技能契约（AP-07）
- 新目标：首次可归因外部真实用户调用（`stat:src` 出现非自检来源）

**关联定理**：无（这是分发问题，非判定问题）

## NR-04：npm 包发布作为 MCP 分发主渠道

**假设**：npm 包是 MCP 分发的标准渠道。

**投入**：2 轮排查（2026-08-06），约 3 小时。

**实测结果**：
- 同名包 `roboparts-mcp` 已被第三方 Crawde（robopartsai.com）占用
- 我方 npm 完全缺席（两个 legacy Publish token 被平台 2FA 策略 403）
- ResolveMesh/FoundryNet 等同赛道均不走 npm，走 hosted Streamable HTTP + 官方 Registry
- 我方已跑在 Pages Functions 上加 `/mcp` 路由，纯自动化可完成

**结论**：**降级为 P2**。npm 不在关键路径上。行业已转向 hosted Streamable HTTP + 官方 MCP Registry。

**反哺建议**：
- npm 降为 P2，仅在换发 Granular Access Token 后被动维护
- 主线走 hosted + Registry（已完成）
- 新目标：第三方目录站（Smithery / Glama / LobeHub）被动收录率

**关联定理**：无（这是分发策略问题）

## NR-05：Tier-A 注水治理后 KPI 提升

**假设**：Tier-A 注水治理（降低虚假 Tier-A 条目）会提升平台数据质量 KPI。

**投入**：1 轮飞轮运行（2026-08-09），约 2 小时。

**实测结果**：
- 73 条 vendor-scope 首页来源降级为 Tier-B
- 2 条编造 GitHub 源（XDA-007/008）隔离
- `trust KPI` 归位 `traceable_pct`：57.91% → 47.32%（**下降**）
- 棘轮基线诚实松动：95→97 / 30→32 / 55.2→47.32

**结论**：**KPI 下降，但这是正确的下降**。Tier-A 注水治理的本质是"把虚高数字回归真值"，KPI 下降不是失败，是诚实化的代价。

**反哺建议**：
- 停止以 KPI 提升为目标——诚实化必然导致 KPI 下降
- 新目标：`traceable_pct` 维持 > 45% 且每条 Tier-A 有一手可核验出处
- 棘轮基线必须诚实松动（L1.71/72），带 `_adjustments` 自证

**关联定理**：T3（关于诚实边界的负结果）——诚实化必然导致 KPI 下降，这是正确方向而非失败。

## NR-06：竞品 npm 下载量作为己方指标

**假设**：竞品 npm 下载量 6 次可代表我方分发能力。

**投入**：0（一次误记，后续 1 轮纠正）。

**实测结果**：
- 周下载 6 是竞品 Crawde 的包，我方真值 0
- "渠道综合 27 分由 npm 70 分撑底"随之失效
- 此前对分发能力判断偏乐观

**结论**：**纠正**。指标污染——把竞品指标当己方指标。

**反哺建议**：
- 周报中所有指标必须标注来源实体（竞品/己方/行业）
- 新目标：指标污染检查纳入 CI 闸门

**关联定理**：T3（关于诚实边界的负结果）——指标污染与假绿同源，都是"把不是自己说的当成自己说的"。

## NR-07：中文 SERP 外链建设

**假设**：中文 SERP 外链建设是冷启动唯一杠杆。

**投入**：2 轮调研（2026-08-05 至 2026-08-06），约 6 小时。

**实测结果**：
- 前 5 条中文 SERP 中 3 条为 SEO 站群软文农场（同源换地域词复制）
- 真人层已被截流，新域名无胜算
- 但软文在 AI 引用层无结构化数据与 license
- 英文 SERP 同样被大站截流，但英文站群对 AI 引用影响更小

**结论**：**中文 SERP 降为副线**。中文 SERP 是站群农场的战场，新域名无胜算。但 AI 可引用数据层是真空地带——软文无结构化数据、无 license、无 API。

**反哺建议**：
- 中文 SERP 降为副线，资源转向 AI 可引用数据层
- 新目标：AI 爬虫命中量（`Googlebot` 19→43，`Meta-ExternalAgent` 175 成最大 AI 爬虫）

**关联定理**：无（这是分发策略问题）

## NR-09：单一标量适应度做多目标进化

**假设**：可用单一标量（如 benchmark 分数）作为长期适应度函数，驱动系统自我改进。

**投入**：2 轮调研（2026-10-13），约 3 小时。

**实测结果**：
- Darwin Gödel Machine（arXiv 2505.22954）用 benchmark 分数作适应度
- 本项目已有指标污染前科（NR-06：竞品 npm 量当己方指标）
- 单一标量适应度在本项目语境下是危险的

**结论**：**否决**。单一标量适应度会被指标污染。本项目必须用多目标适应度。

**反哺建议**：
- 多目标适应度：保留 `可判定对增量`、`溯源等级`、`unknown 削减`、`闸门成本` 四个维度
- 红线：不得用单一标量做长期适应度
- 新目标：`fitness(n, axis) = Σ_axis Δ可判定对 × 溯源可信度 − 闸门成本`

**关联定理**：T3（关于诚实边界的负结果）——单一标量适应度与指标污染同源，都是"把多维信息压缩为一维"。

## 元模式：负结果的三层结构

本项目已验证的负结果可分为三层：

| 层次 | 特征 | 示例 | 反哺方式 |
|---|---|---|---|
| **L1 取证层** | 取证投入与目标不成比例 | NR-01（fill_pct）、NR-02（合规标签） | 转向"更好的 unknown 处理" |
| **L2 分发层** | 曝光 ≠ 使用 | NR-03（MCP）、NR-04（npm）、NR-07（SERP） | 修接入路径，而非增加曝光 |
| **L3 指标层** | 指标污染 / 诚实化代价 | NR-05（KPI）、NR-06（npm 量）、NR-09（单一标量） | 多目标适应度 + 指标来源标注 |
