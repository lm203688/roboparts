## 〇、评价标准换轨（这是全篇的地基）

前两份文档用的是**市场缺口**判据（"别人没做、所以有位置"）。本轮换成**创新天花板**判据：

| 旧判据（作废） | 新判据（启用） |
|---|---|
| 赛道里有没有人 | 这个方向**理论上能做到多深** |
| 有没有商业价值 | 有没有**独特的形式化/技术贡献** |
| 冷启动难不难 | 是不是**值得啃的硬骨头** |
| 竞品会不会吞掉 | **能不能定义一个新问题**（而不是回答旧问题） |

**一句话新定位**：
> **RoboParts = 具身系统"组合"的形式化底座**——把神经控制（脑）× 物理躯体（体）× 学习策略（智）做成**机器可校验的组合**，并全程可溯源。
> 不是零件数据库，不是兼容性网站，是**具身设计的类型系统 + 组合演算 + 溯源层**。

## 一、原三方向的"天花板"重估（含放弃建议）

| 方向 | 若停留在原形态 | 天花板 | 判定 |
|---|---|---|---|
| **一、学术验证** | 把数据打包发数据集 | **低**（这是分发动作，不是 R&D） | ⚠️ **不构成"方向"，降级为副产品** |
| **二、神经-躯体对接** | 建个 API 桥接 | **中→高**（取决于是否形式化） | ✅ 保留并**升维**（见 D5） |
| **三、小模型训练规范** | 写训练数据 schema | **中→高**（取决于是否做成协同设计） | ✅ 保留并**升维**（见 D4） |

**明确的放弃建议**：**方向一不应作为"研发方向"存在**。
- 理由：把 `entities.json` 转成 Croissant 元数据、挂 Zenodo 拿 DOI——这是**一次性的工程杂活**，零创新，天花板封顶在"数据集被引用几次"。
- 处理：**降级为 Phase A 的一个交付动作**（顺手做掉），不占用方向位。它的唯一价值是给新方向提供"被引用的入口"。

## 二、更大的想象空间：三个新方向（需打基础）

下面三个是"啃硬骨头"的方向。每个都给：**硬骨头在哪 / RoboParts 独有资产怎么咬合 / 2026 前沿锚点 / 风险**。

### D4 · 形态-控制协同设计底座（Morphology–Control Co-Design Substrate）

**硬骨头**：给定任务，**同时**优化"躯体（选哪些零件、怎么连）"和"控制器/策略"。这是 NP-hard 的组合×连续混合优化，且形态一变，已学策略就失效（knowledge transfer 问题）。

**2026 前沿锚点（已核实）**：
- arXiv 2603.19582（2026-03）：GNN/GAT 驱动的软体机器人协同设计——**把机器人表示为图**，图形化策略作为"形态与控制的接口"。原文结论："graph-structured policies provide a more effective interface between evolving morphologies and control"。
- BRIDGE（arXiv 2609.03497，2026-09）：开源人形平台，**用协同设计**优化形态，对标 Bumi/K1/**Toddlerbot**（Toddlerbot 已在 RoboParts 生态内）。
- AdaControl（arXiv 2608.23100）：双层优化，指出"形态智能 vs 真实潜力"的解耦。
- Cambridge《Co-design is powerful and not free》：协同设计在"形态与任务失配"时收益最大。

**RoboParts 的独有咬合点**：
> 2026 前沿全在用**图**做形态表示，但**没有一份"标准化、且经过兼容性校验"的零件图**。RoboParts 的 802 实体 + ISO 9409-1 判定 + signal contract **就是这个缺失的零件图底座**。
- 它比 CAD 图多一层：**兼容性已经判定过**（哪些零件能装到一起），协同设计的搜索空间因此被合法剪枝。
- 这是别人**做不了**的（他们得自己建零件库 + 判定引擎）。

**要打的基础**：
1. 把 registry 导出为**标准形态图**（parts = nodes, interfaces = typed edges）。
2. 定义**形态适应度**指标（复用 BRIDGE 的 kinematic retargeting fidelity 思路）。
3. 一个最小 demo：在 5-10 零件的图空间里跑 GA 协同搜索（flybrain 已有 GA 经验可迁移）。

**风险**：需仿真（MuJoCo/Isaac）loop，算力成本高于纯数据处理；但可用小规模 + 离线预计算控制。

### D5 · 具身组合演算 / 兼容类型系统（Embodiment Composition Calculus）

**硬骨头**：把"两个零件能不能装一起"从**启发式规则**升级为**可证明的组合类型系统**——零件、控制器、信号都有**类型**，组合是**类型检查**，不匹配即**类型错误**。

**2026 前沿锚点（已核实）**：
- ARIA「Safeguarded AI」（英国政府资助）：**用范畴论**为 AI 安全建模——"build formal models of complex systems... must have the same logical structure as the real system, correctly representing the morphisms between many different types of objects. Category theory gives you a modular and compositional way of doing this."（Quanta 2026-03）
- CSLib（Lean）："a developer would be able to derive reliable and secure systems **compositionally**, by putting together pre-verified components"——**组合式验证**范式。
- LIFR / VERIFAI 2026：**契约合成**（contract synthesis）+ 验证工件语义复用。

**RoboParts 的独有咬合点**：
> 现有 `signal_interface.schema.json`（GAP-G2）是**静态 schema**；把兼容性升级为**类型演算**后，`add_mechanical_interface.py` 里的规则判定 → **一个可证明的类型检查器**。
- 独有资产：ISO 9409-1 的 9 种标号 PCD + 转接盘结论（100% 需转接）+ signal 三层（脉冲/感觉/运动）——这些是**现成的类型构造子**。
- 产出形态：一个 `compose(brain, body) -> EmbodiedSystem | TypeError` 的函数式接口。**这是全新问题定义**，不是回答旧问题。

**要打的基础**：
1. 形式化语义：机械兼容 = 法兰类型匹配；电气 = 电压/协议类型；信号 = 脉冲/感觉/运动契约。
2. 原型：先用**轻量依赖类型**（Python/TypeScript 的 effect system 或 Rust trait bound）而非直接上 Lean——**先证明概念，再上重武器**。
3. 与 NCP（sepahead/NCP）的关系：NCP 是**运行时线协议**，本方向是**静态类型层**，互补。

**风险（必须诚实）**：范畴论/Lean 形式化是**多年期研究计划**，独立开发者风险极高。**缓解 = 分三步**：①轻量 effect system 原型（1 月）→ ②发表方法论文（占学术位）→ ③视反馈决定是否上 Lean。**不要一上来就写 Lean 定理证明。**

### D6 · 具身全链路溯源（Embodied Provenance）

**硬骨头**：让一个具身系统的行为**从神经元一路追溯到行为**：神经元 → 拓扑（flybrain motif）→ 躯体（RoboParts 零件）→ 策略（小模型）→ 行为（日志），全程**机器可校验**。

**2026 前沿锚点（已核实）**：
- Croissant 1.1（MLCommons）已采纳 **W3C PROV-O** 做 provenance，700K 数据集在用 → **生态已就绪**。
- flybrain **已经在用 W3C PROV-JSON（70/70 断言通过）**——这是 RoboParts 天然可接的现成溯源。
- EU AI Act 对"可追溯性"的硬门槛 → 合规刚需。

**RoboParts 的独有咬合点**：
> 全球**没有**一个系统能做到"神经拓扑 → 物理躯体的端到端溯源"。flybrain 有 PROV（脑侧），RoboParts 有 registry（体侧），**两者 provenance 一拼就是完整链路**。
- 这是**生态互补型创新**：单看都不新，**合起来是新东西**。

**要打的基础**：
1. 定义跨层 provenance schema（复用 PROV-O 的 entity/activity/agent 三元）。
2. RoboParts 每个零件声明加 `prov` 字段（出处 = 厂商 datasheet + 抓取时间 + 校验状态）。
3. 一个 demo：从某 flybrain motif 追溯到它"能驱动哪些 RoboParts 躯体"，每跳带 provenance。

**风险**：低（纯数据 + schema，无算力需求）。**这是三个新方向里最容易起步的。**

### （可选）D7 · 兼容零件的仿真模型自动生成

把"已判定兼容的零件组合"**自动生成可跑的仿真模型**（URDF/SDF/MJCF）。
- 前沿锚点：Sleem45 的 CAD→URDF+Gazebo 自动验证流水线、text-to-cad（11K stars，NL→STEP/URDF/SDF/DFM）。
- **差异化**：他们从**CAD 或文本**出发；RoboParts 从**已校验兼容的零件图**出发——生成的是"**保证装得上**的组合体"，不是单个零件。
- 判定：**收益中，但已有强竞品（text-to-cad）**。建议**作为 D4 的一个子模块**而非独立方向。

## 三、技术迭代方向（存量资产的"下一跳"）

存量资产不是静态的，每个都有明确的升维路径：

| 存量资产 | 现状 | 下一跳（迭代方向） |
|---|---|---|
| 兼容性判定引擎 | 启发式规则（`negative_compat.json` 81 条） | → **形式化类型检查器**（D5）；规则从"列举"变成"推演" |
| `signal_interface.schema.json` | 静态 JSON schema | → **行为契约**（session types / 时序逻辑），能表达"握手/时序/失败恢复" |
| `training_dataset.json` | 静态多模态导出 | → **形态条件化数据集**（图条件 + 策略），直接喂 D4 的 GNN 策略 |
| neurorobotics GAP 地图 | 静态情报（GAP-G1~G7） | → **活的 gap tracker**（自动扫描新论文/新品，更新 gap 状态） |
| flybrain motifs | 静态快照（40 motif） | → **参数化拓扑生成器**（按目标躯体反向生成拓扑） |
| 机械声明率 5.69% | 缺口（被当短板） | → **主动 gap 研究**：为什么是 5.69%？把"缺口"本身变成一篇实证研究（哪些品类天然不可声明） |

**关键洞察**：5.69% 这个"短板"在创新框架下**可以转化为资产**——但**表述必须收窄**。

> **【2026-09-23 收窄，见锚点 §6.1】** 原写「它是一份 ISO 9409-1 覆盖边界的实证证据」——**过强，已作废**。
> 核实反例：`ACT-001 DYNAMIXEL XM540` 的 `status=partial`，其 `declared_note` 明写「非 ISO 9409-1 法兰」
> ⇒ 该零件**有**机械接口，只是不标准。「未声明」混淆了 **(i) 厂商未公开规格**（真缺口）与
> **(ii) 本就采用自研接口**（生态碎片化，非缺口）。
> Laya 421M 对「是否为关于标准的诚实实证发现」以 conf=0.9226 答**否**（P=0.0774），作反方意见采纳。
>
> **修正后的合法主张**：5.69% 是「公开可判定粒度上的标准登记率」，其低值由 (i)/(ii) 两种未区分成因构成。
> 在完成 (i)/(ii) 分类之前，不得把它单独当标准覆盖边界的实证证据。
> **残留价值更大**：把 (i)/(ii) 分类**做出来**，是一个尚未做、可做、没人做过的研究动作
> —— 方向从「把缺口当证据」改为「把**缺口的成因分类**当研究」。

## 四、后续发展规划（Phase A–E，演进轨迹）

前两版只给了 8 周 MVP，**缺长期轨迹**。补上：

```
Phase A｜骨架期（现在 → 6 周）     「把资产变成可组合的形式对象」
  ├─ A1 方向一降级：Croissant 元数据 + Zenodo DOI（顺手做，拿引用入口）
  ├─ A2 registry → 标准形态图（parts=nodes, interfaces=typed edges）
  ├─ A3 定位重写：GAP-G2 → "NCP 的静态类型层"（避重复造轮子）
  └─ A4 D6 起步：跨层 provenance schema（最易，先做）

Phase B｜形式化期（1-3 月）        「把组合从规则升级为演算」
  ├─ B1 轻量 effect-system 原型：compose(brain, body) -> Result | TypeError
  ├─ B2 三轴类型语义：机械(法兰) / 电气(电压协议) / 信号(脉冲·感觉·运动)
  ├─ B3 方法论文投稿（占学术位，非数据集 paper）
  └─ B4 视反馈决定是否上 Lean/范畴论重武器

Phase C｜协同期（3-6 月）          「形态与策略联合优化」
  ├─ C1 形态图 + GNN 策略（对标 arXiv 2603.19582）
  ├─ C2 形态适应度指标（对标 BRIDGE 的 retargeting fidelity）
  ├─ C3 最小 GA 协同搜索 demo（5-10 零件图空间）
  └─ C4 与 flybrain 拓扑联调（脑×体×策略 闭环）

Phase D｜溯源期（6-9 月）          「端到端可追溯」
  ├─ D1 全链路 provenance：neuron → topology → body → policy → behavior
  ├─ D2 对齐 Croissant 1.1 / W3C PROV-O（生态就绪）
  └─ D3 对齐 EU AI Act 可追溯性要求（合规叙事）

Phase E｜生态期（9-12 月）         「开放与互操作」
  ├─ E1 registry 作为公共品开放（MIT/CC-BY）
  ├─ E2 与 NCP / NRP 互操作（做它们的躯体层，不另起炉灶）
  └─ E3 开源 kit + 学术合作（flybrain 联合发表）
```

**决策闸门**（每期结束问三个问题）：
1. 这一期是否产出了**别人做不出的**东西？
2. 是否**定义了新问题**（而非回答旧问题）？
3. 下一期是否更接近"具身组合演算"这个核心命题？
> 三个都否 → 该方向**止损**，不因沉没成本续投。

## 六、一句话结论

> **原三方向里，方向一应放弃（降级为副产品），方向二/三应升维；真正的创新空间在三个新方向——D4 协同设计底座、D5 具身组合演算、D6 全链路溯源。核心命题从"做个零件兼容平台"升级为"做具身系统的类型系统与组合演算层"。**

**三个新增的诚实边界**：
1. D5（范畴论/Lean）是**多年期**研究，独立开发者必须分步，不可一步到位。
2. D4 需要仿真 loop，**算力是真实约束**，必须小规模起步。
3. D7 有强竞品（text-to-cad），**不独立立项**。
