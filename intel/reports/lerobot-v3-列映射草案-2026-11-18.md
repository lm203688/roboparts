## 0. 一句话结论

RoboParts 的数据形态是**静态零部件库 + 兼容性关系图**（659 组件、10304 条已判定兼容边、20 项标准）；而 LeRobotDataset v3 的形态是**多模态时序轨迹**（`observation.state` / `action` / `observation.image` / `timestamp` 逐帧）。

二者**不是同类**，不存在"RoboParts 字段 → v3 传感/动作列"的直接映射。正确路径是：**RoboParts 作为先验/元数据注入层**，把"已知真值装配对"的可验证约束喂给 v3 数据集的任务层，**而非伪造 v3 的轨迹列**。

---

## 1. 诚实边界（不可破，须保留在对外文档中）

RoboParts 平台**明确不提供**以下能力（均出自 `meta.modalities` / `meta.honesty` / `meta.access.honest_limits`，已核实）：

| RoboParts 明确不提供 | v3 对应列 | 处置 |
|---|---|---|
| 原始图像 / RGB(-D) 流 | `observation.image.*` | `not_provided`（`modality_details.vision.note` 明文：本平台不提供原始图像流，消费方须自备相机） |
| 原始六维力/力矩传感时序 | 力觉流 | `not_provided`（`force` 仅声明级 `torque_nm`/`weight_kg`，无 F-T 时序） |
| 原始触觉传感时序 | 触觉流 | `not_provided`（`tactile.note` 明文：声明级/类别级，无原始触觉传感） |
| 机器人本体运动轨迹 | `observation.state` / `action` | `not_provided`（RoboParts 无本体、无相机、无演示数据） |
| 跨厂商可直接横向比较的实测 A 级条目 | 任何实测列 | `not_provided`（`honest_limits.cross_vendor_comparable_grade_a = 0`） |

## 2. 可直映射（RoboParts 字段 → v3 元数据/任务层）

映射目标是 v3 的**元数据层**（`meta/info.json` 扩展或自定义 `meta/roboparts.json`），**不是**逐帧传感列——因为 RoboParts 字段全部与时间无关。

| RoboParts 字段 | v3 目标 | 判定 | 说明 |
|---|---|---|---|
| `components[].id` | `meta/roboparts.json`（`part_id`） | 直映射 | 静态标识，659 全有 |
| `components[].name` / `name_en` | 同上 | 直映射 | |
| `components[].manufacturer` | 同上 | 直映射 | |
| `components[].category` | 同上 | 直映射 | 16 类（actuators 220 … integrated_joints 1） |
| `components[].type` | 同上 | 直映射 | 如 `smart_servo` |
| `components[].specs.{protocol,interface,position_resolution,voltage,torque,speed,weight}` | 同上 | 直映射（降 dtype） | **声明级参数，非实测**；键集 659/659 全覆盖 |
| `components[].modalities` | 同上（模态覆盖） | 直映射 | geometric 121 / electrical 44 / force 93 / tactile 47 / vision 39 |
| `components[].modality_details.force.{torque_nm,weight_kg}` | 同上 | 直映射 | 仅当 `force.declared=true`（93 项） |
| `components[].modality_details.force.force_control_precision_nm` | 同上 | **条件降级** | 657/659 为 `null` → 降级 `not_provided`；仅 2 项非空可映射 |
| `components[].evidence.source_tier` | 同上（溯源） | 直映射 | A=189 / B=245 / C=225 |
| `components[].evidence.confidence` | 同上 | 直映射 | |
| `components[].standards.{caee060_relevant,iso22166_relevant,bus_class,ros2}` | 同上 | 直映射 | 与 20 项标准关联 |
| `meta.provenance` / `meta.totals` | 数据集级溯源 | 直映射 | 全库口径 |
| `compatibility_edges[].{a,b,overall_compatible,compatibility_score,interaction_type}` | 任务层 / 动作先验 | **条件映射（需扩展）** | 见 §3 |

## 3. 需要扩展的（非 v3 原生概念）

v3 没有"兼容性边 / 零部件库"这一概念。落地需二选一：

- **A. meta 侧注入（推荐，零侵入）**：新增 `meta/roboparts.json`，存放零部件库 + 兼容性边。不改 v3 核心，RoboParts 消费方（TurboVLA / Isaac / MoziSim）自行解析。
- **B. 任务层注入（贴近训练管线）**：把"已知真值装配对"写进 `meta/tasks.parquet` 或 `language_persistent` 行，让 VLA 在训练时把"能否安装"作为任务条件。需定义 recipe（YAML）。

推荐 **A 先行**，B 视训练管线需要跟进。

### 关键上游事实（供实现参考）

- v3 三支柱：
  - **Parquet**：低维高频信号（states / actions / timestamps），`data/chunk-*/file-*.parquet`
  - **MP4**：视觉帧按相机分片，`videos/*.mp4`
  - **meta**：`meta/info.json`（canonical schema：features / shapes / dtypes / FPS / path templates）、`meta/stats.json`（归一化统计）、`meta/tasks.parquet`（任务→整数 ID）、`meta/episodes/`（分片：lengths / tasks / offsets）
- 语言扩展（可选）：
  - `language_persistent`：跨帧广播（subtask / plan / memory）
  - `language_events`：精确帧事件（interjection / vqa / speech）
  - 行结构：`{role, content, style, timestamp, camera, tool_calls}`
  - `meta/tasks.parquet` 仍是 task 权威源；`${task}` 特殊绑定总读它
- v2.1→v3 迁移：聚合 per-episode → `file-NNN.parquet` / `file-NNN.mp4` + `meta/episodes` 偏移。
- `finalize()` 必须在 `push_to_hub()` 前调用（[PR #1903](https://github.com/huggingface/lerobot/pull/1903)），否则 Parquet footer 缺失、数据集损坏。

## 4. 未决 / 风险

1. **`specs` 是厂商声明值**：全部边 `evidence_basis` 为同一句"基于厂商公开声明字段的规则推断，非实测；未声明维度记为无法判定，不计入分子也不计入分母；判 true 至少需一项硬约束有双方声明"。映射时必须保留这句话，不得声称实测。
2. **`interaction_type` 三类**：`bus_coupling` 7189 / `flange_mount` 2485 / `connector_insert` 630。映射到 v3 动作空间需类别化，无现成约定。
3. **A 方案是 RoboParts 自定义扩展**：不污染 v3 标准，但消费方需额外解析；若消费方只认标准 v3，则 A 无效。
4. **本草案不声称 RoboParts 能生成 v3 轨迹**：平台无本体/相机/演示数据，此边界必须在对外文档与数据 schema 中显式保留。
