# 开源机器人的数据主权：你采的每一条轨迹，都应该属于你

> 本文首发于 [RoboParts 开源机器人兼容性平台](https://roboparts.cc)。

你用一台 Trossen OpenArm 做遥操作，花 6 个月采集了 10 万条抓取轨迹；或者你在自己搭的 LeRobot-Humanoid 上跑了半年数据采集。这些数据属于谁？

如果你用的是某云厂商的机器人平台，答案可能是：属于平台。你的数据被用来优化他们的通用模型，甚至被卖给第三方，而你一分钱都拿不到。

这不是假设。2024 年，某头部机器人数据平台被曝出将用户的遥操作数据用于训练商业模型，引发社区强烈反弹。

**对开源机器人构建者，这件事尤其讽刺**：你选择开源硬件、开源控制栈、开源模型，恰恰是为了不被锁死在某个厂商手里；结果最有价值的一环——你亲手采集的物理世界数据——反而被闭源平台拿走了。

---

## 一、机器人数据的特殊性

机器人数据比其他 AI 数据更敏感：

| 数据类型 | 敏感度 | 价值 |
|---|---|---|
| 遥操作轨迹 | 高 | 直接反映操作者技能 |
| 环境地图 | 高 | 暴露物理空间布局 |
| 力/触觉反馈 | 极高 | 可用于反推物体材质、重量 |
| 失败案例 | 极高 | 暴露系统弱点 |
| 人体交互数据 | 极高 | 隐私、安全 |

**关键点**：机器人数据不仅是"训练素材"，更是**物理世界的指纹**。一旦泄露，攻击者可以重建你的工作环境，甚至推断你的商业机密。

对开源项目而言还有一层：**数据是社区里最难复现的资产**。天工 TienKung 的图纸可以下载，Unitree G1 的 SDK 可以调用，OpenVLA 的权重可以拉取——但你在自己场景下采的那批带触觉反馈的失败案例，全世界只有你有。

---

## 二、现有平台的数据陷阱

### 陷阱 1：服务条款默认授予平台所有权
多数机器人平台的服务条款包含类似表述：

> "用户上传的数据，平台有权用于改进服务、训练模型，并可向合作伙伴提供匿名化数据。"

"匿名化"在机器人领域几乎不可能——轨迹数据的空间分布特征足以识别特定场景。

### 陷阱 2：数据锁定
平台提供便捷的 SDK 收集数据，但导出时：
- 格式不开放
- 需要付费解锁
- 限制导出次数

**这直接违背开源工作流**：LeRobot 生态的价值就在于数据集能在 HuggingFace 上自由流转、被社区复用。一个不能自由导出的格式，等于把你的数据从开源生态里摘了出去。

### 陷阱 3：二次商业化
你的数据被用来训练通用模型，然后以 SaaS 形式卖回给你。

## 三、RoboParts 的解决方案：零知识架构

我们设计了一套**用户完全拥有数据**的架构：

### 3.1 客户端加密

所有数据在离开机器人之前就完成加密：

```
明文数据 → AES-256-GCM 加密 → 密文上传
                ↑
         密钥 = PBKDF2(用户密码, salt, 100000次)
```

- 加密在浏览器/机器人本地完成
- 平台只存储密文，**无法解密**
- 密钥由用户密码派生，**平台不保存密钥**

### 3.2 数据迁移

用户可以随时：
1. 下载加密数据包（.roboparts 格式）
2. 在新机器人上输入密码解密恢复
3. 无需平台参与

**数据迁移路径**：
```
Robot A → 加密导出 → 用户持有 → 解密导入 → Robot B
```

对开源构建者最实际的用法：在 OpenArm 上采的数据，解密后直接转成 LeRobot 数据集格式推到 HuggingFace；或者把在 roboto_origin 上验证过的策略数据，迁移到 Unitree G1 上做跨平台微调。**平台不参与，也就不会成为瓶颈。**

### 3.3 授权市场（可选）

如果用户**自愿**将数据授权给制造商：
- 用户明确勾选授权范围
- 数据以匿名化统计形式出售
- 收益分配：**80% 归用户，20% 平台佣金**
- 用户随时可撤回授权

## 四、技术实现

### 加密流程

```javascript
// 用户密码派生密钥
const key = await crypto.subtle.deriveKey(
  { name: "PBKDF2", salt, iterations: 100000, hash: "SHA-256" },
  await crypto.subtle.importKey("raw", password, "PBKDF2", false, ["deriveKey"]),
  { name: "AES-GCM", length: 256 },
  false,
  ["encrypt", "decrypt"]
);

// 加密数据
const ciphertext = await crypto.subtle.encrypt(
  { name: "AES-GCM", iv },
  key,
  data
);
```

这由平台佣金收入覆盖，**用户免费**。
