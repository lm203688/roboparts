# RoboParts 任务追踪系统

## 六步闭环工作流

```
情报收集 → 分析研判 → 决策采纳 → 开发任务 → 测试验证 → 部署上架
    ↑                                                        ↓
    └──────────────────── 效果追踪 ←────────────────────────┘
```

## 任务状态定义

| 阶段 | 状态 | 说明 |
|------|------|------|
| 情报收集 | 待收集 / 收集中 / 已收集 | 从日报、周报、外部渠道收集信息 |
| 分析研判 | 待分析 / 分析中 / 已分析 | 对情报进行趋势分析、价值评估 |
| 决策采纳 | 待决策 / 已采纳(P0/P1) / 观察(P2) / 拒绝 | 决定是否进入开发，分配优先级 |
| 开发任务 | 待开发 / 开发中 / 开发完成 | 拆解为具体任务并执行开发 |
| 测试验证 | 待测试 / 测试中 / 测试通过 / 测试失败 | E2E测试、回归测试、验收 |
| 部署上架 | 待部署 / 部署中 / 已部署 / 已回滚 | 部署到Cloudflare Pages，线上验证 |
| 已闭环 | 已闭环 | 全部阶段完成，效果可验证 |

## 任务优先级

- **P0**：紧急/阻塞性问题，本周必须完成
- **P1**：重要功能/改进，2周内完成
- **P2**：优化/储备，1-2月内完成

## 文件命名规范

| 文件类型 | 命名格式 | 示例 |
|----------|---------|------|
| 周任务清单 | `weekly-tasks-{YYYYMMDD}.md` | `weekly-tasks-20260727.md` |
| 单个任务卡 | `task-{TASK-ID}.md` | `task-T001-data-sync.md` |
| 测试报告 | `test-report-{YYYYMMDD}.md` | `test-report-20260727.md` |
| 部署记录 | `deploy-log-{YYYYMMDD}.md` | `deploy-log-20260727.md` |

## 闭环判定标准

一个任务被标记为"已闭环"需同时满足：
1. ✅ 开发完成，代码已提交
2. ✅ 测试通过，E2E测试全绿
3. ✅ 部署上线，Cloudflare Pages构建成功
4. ✅ 线上验证，核心功能冒烟测试通过
5. ✅ 效果可衡量，有明确的成功指标

## 触发机制

- **每日**：综合巡检任务（每日02:30）收集情报+健康度检查
- **每周**：综合运营任务（每周一03:00）执行完整六步闭环
- **按需**：遇到P0紧急情报时，随时触发快速闭环
