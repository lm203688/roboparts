## 摘要

两个机器人末端装置能否共装，在产品数据实践里被当作一个**判定问题**：给出描述，系统就能判兼容或不兼容。我们在一份经过审计的机器人部件目录（656 个可组合节点、214,840 个无序对、329 家厂商）上证明：判定率本身是证据门槛的函数。固定节点集不变、只收紧证据规则，可判定电气对的占比从 64.764%（D0，含占位的类型标签相等）降到 0.00512%（D1，真实标号相等）、0.00372%（D2，类型+针序+性别齐备）、0.00047%（D3，人工 locus 校正到器件对器件真互插）——落差约五个数量级。机制可测：553 个电气端口中 528 个（95.48%）类型为占位符 `ELEC:UNKNOWN`；D0 的 139,139 对里 139,128 对（99.992%）是 UNKNOWN×UNKNOWN 自碰撞。在三轴测量与按厂商整群 bootstrap（B=1000）下，电气轴在每一种定义下都是最弱轴，比机械轴低一到三个数量级。我们进一步在共装层 360 对上（mountable=0）建立零的五分类（Z1 端口耗尽、Z2 类型不匹配、Z3 器件侧未声明、Z4 宿主侧未声明、Z5 角色不互补），并证明上界命题 P1：宿主 h 工具侧有 p(h) 个独立供电、独立寻址的连接器位时，可共装器件数 k ≤ p(h)。UR3e 与 UR5e 各只有 1 个工具侧位（p=1），故任意 k≥2 的共装在结构上不可满足，与数据完备性无关；Z1+Z5 已占 297/360 = 82.5%，补证据不能消除。两项外部清点指向同一方向：机器人硬件信息模型 HRIM（21 个类模型、3 个实例数据）机械对接字段为 0、连接器级电气字段为 0；UR+ 市场页 528 个产品接口字段为 0。结论：兼容性是一个测量问题，其答案取决于被隐式选定的门槛；而其中相当比例的零是结构性的，不是数据质量问题。

**关键词：** 机器人末端执行器；接口兼容性；决策支持；产品数据；部分约束；共装；HRIM；UR+ 市场

## 1. 引言

配置一台工业或协作机器人系统——选臂、选末端、选传感器、再选其间线缆——在实践中仍由经验丰富的系统集成师完成。Aarhus 大学 Tola 等人在立场论文中直陈：*"To our knowledge, no mature public robot system configurators exist, leaving the task of configuration up to experienced system integrators"*（据我们所知，尚无成熟的公开机器人系统配置器，配置工作仍依赖有经验的系统集成师）[1][V]。同一篇论文把挑战 A 到 G 列为：硬件标准化缺失、ISO 9409-1 法兰标准被用得半半拉拉、同一工业协议下设备兼容性不清、以及没有任何一个标准同时定义设备的机械与通信接口 [1]。

此后有两类回应。一类在厂商生态之上搭建配置器与应用构建器——UR+ 与 ABB 应用构建器是最接近机器人配置器的工业软件，但它们把臂锁死在单一厂商，对其余设备暴露甚少 [1]。另一类搭建信息模型，其典范即 HRIM（Human-Robot Interaction Module），承诺用统一表示描述来自不同厂商的机器人硬件并加以组合 [2]。

两类回应共享同一个隐含动作：把兼容性当作**判定问题**——描述一旦存在，系统即可判定两器件是否互插。本文问的是这个动作之前的问题。我们不问"缺了哪些描述"，而问：**当我们要求的证据量变时，判定率实际上是多少？**以及**由此产生的零里，有多少是再收集证据也消除不掉的？**

我们在一份审计后的机器人部件目录（RoboParts）上测量：868 个实体，其中 656 个可组合节点构成 214,840 个无序对，来自 329 家厂商 [E]。我们分四步收紧证据门槛（3.3 节），观察到五个数量级的落差（4.1 节）。我们在机械法兰、电气连接器、信号定义三轴上分别测量，并做按厂商整群 bootstrap（4.2 节）。我们对共装层 360 对逐一分类其零（4.3 节）。然后我们证明一条把此事从经验中抽离的命题（4.4 节）。最后，我们检查两个根本不在本目录里的外部对象——HRIM 仓库与 UR+ 市场——发现二者同样缺失接口描述（4.7 节）。

定位句贯穿全文：**前人把兼容性当作判定问题（给定描述即可判定）；本文证明它是测量问题（判定率本身是证据门槛的函数，跨五个数量级），并给出零的结构性上界。**

*贡献。*

1. 四级可判定性阶梯（D0–D3）与实测五个数量级落差，机制识别为占位端口自匹配（528/553 电气端口为 `ELEC:UNKNOWN`）。
2. 分层测量：电气轴在每一种定义下均为最弱轴，低于机械轴一到三个数量级，配宽幅厂商整群置信区间。
3. 共装层零的分类学 Z1–Z5，并证明 Z1+Z5 = 297/360 = 82.5% 不可由补证据消除。
4. 命题 P1（端口预算上界）及其证明与三条推论，含证据单调不变性。
5. 法兰标号是套件属性而非器件属性——同一夹爪依所购耦合套件不同可对三种 ISO 标号。

## 2. 相关工作

**机器人配置与系统集成。** Tola 等 [1] 把配置框为标准化缺失问题，提出 answer set programming 与协同仿真两条路线；其后续工作 [3] 对配置任务做形式化。Siltala 等 [4] 与 Zheng 等 [5] 从工业工程侧处理系统集成与产品可配置建模；Chaumet 等 [6] 把基于约束的配置做成组合服务。这些工作无一测量：在真实部件总体上，可用证据到底多常足以判定一对。

**硬件信息模型。** HRIM [2] 是被引用最多的开源机器人硬件信息模型；我们直接清点其仓库（4.7 节），发现其"信息"是 ROS 消息话题，不是装配几何或连接器针脚。ISO 9409-1 定义圆形安装法兰，但 Tola 等已指出厂商用得不齐 [1]；我们的数据补充：同一器件依套件不同可呈现三种 ISO 标号（4.5 节）。UR+ 市场 [7] 是我们能检视的最大末端产品目录；其 528 个产品不带任何接口字段。

**部分与三值约束。** 暂不能下的判断不是"假"，是"未知"。这是动态与部分约束满足 [8][9]、面向不完全性的三值逻辑 [10]、以及配置社区把 unknown 当作第三态 [11] 的经典领地。我们在这条轴上的贡献不是新逻辑，而是一项**实证分离**：共装层 63 个 unknown 判决里，只有一部分是"待证据的未知"（Z3、Z4）；其余是"现在就已定的零"（Z1、Z5），再多证据也不动。分类学（4.3 节）就是把这一分离显式化。

**空白。** 据我们阅读，此前无人（i）在真实部件总体上把判定率当作证据门槛的函数来测量，（ii）界定多大比例的不兼容是结构性而非证据性的，或（iii）通过独立清点证明：最主要的信息模型与最主要的市场都省略了判定所需的对接字段。

## 3. 语料与方法

### 3.1 目录

RoboParts 审计语料存于九张 JSON 表：`entities.json`（868 实体）、`morphology_graph.json`、`mechanical_interfaces.json`、`electrical_interfaces.json`、`co_mount.json`、`robot_tool_side.json`、`compatibility.json`、`compose_semantics.json`、`evidence_valuation.json`。隔离 22 个泛品类占位节点（如无型号的 `SENS-001`）后，可组合集为 **656 节点、214,840 无序对**，来自 **329 家厂商**（在带 manufacturer 字段的可组合节点上去重计数）[E]。隔离后分母缩为 634 节点 / 200,661 对；本文全部阶梯密度用 656/214,840 分母，隔离后重计作为敏感性报告（4.6 节）。

溯源标签贯穿全文：**[V]** 已核一手文件或文献；**[O]** 官方或二手口径未逐字核；**[E]** 本文现算，可用随附脚本（`rp_ladder.py`、`rp_b24.py`、`rp_b2v2.py`）复算。

### 3.2 电气端口实况

目录含 **553 个电气端口、17 个 distinct type id**；其中 **528 个（95.48%）类型为 `ELEC:UNKNOWN`**。端口状态 declared 25 / not_declared 528。**带多于一个 declared 电气端口的节点仅 6 个** [E]。这种不对称——五百个占位对寥寥几个真实标号——是阶梯的实证脊梁。

### 3.3 四级阶梯

固定 656 节点 / 214,840 对总体，只改证据规则 [E]：

- **D0 · 容占位标签相等。** 两端端口类型标签相等即配对，占位也算。
- **D1 · 真标号相等。** 排除 `ELEC:UNKNOWN`，其余标号须相同。
- **D2 · 引擎配对裁决。** 类型、针序、性别齐备时，配置引擎方可下 identity 或 adapter 判决。
- **D3 · locus 校正真互插。** 人工按端口 *locus*（device/adapter/host/cable）逐对重判；只有器件侧端口对器件侧端口才算。

四级按构造嵌套（D3 ⊂ D2 ⊂ D1 ⊂ D0）；所问仅为计数塌缩有多快。

### 3.4 三轴与整群 bootstrap

三轴分测：机械法兰轴（同 ISO 标号 / 两端均 declared / 两端 loose）、电气连接器轴（两端 declared）、信号定义轴（两端 declared）。因方差主要由厂商聚集主导（329 家、大量单品厂商），我们按厂商整群重抽 B=1000（seed=20261109），报告点估计与 95% 分位置信区间 [E]。

### 3.5 外部清点

目录之外两个对象直接清点。HRIM（`AcutronicRobotics/HRIM`，Apache-2.0，archived，最后 push 2019-08-07，71 star）经 git 全树枚举，计类模型、实例数据、机械对接字段、连接器级电气字段 [V]。UR+ 市场页（`universal-robots.com/plus/products/`）检查产品总数与是否存在任何接口筛选器 [V]。

### 3.6 可复算

完整检索式、数据库、访问日期（2026-11-09）、命中数与排除理由，以 PRISMA-ScR 记录落于 `04_ResearchData/PRISMA_ScR.md`；取不到命中数处记 `NOT_RETRIEVABLE` 并注明原因，绝不估算冒充实测。

塌缩是机械性的。139,139 个 D0 对中，**139,128 对（99.992%）是 UNKNOWN×UNKNOWN**——占位碰占位，约等于 528 个占位端口两两相撞的 C(528,2)。排除占位后，仅 11 对共享真实标号；再要求针序与性别，8 对；再经 locus 校正，1 对。11 个 D1 对逐条为：ACT-001×ACT-002（JST-EHR-03）；ACT-028×GRIP-002、ACT-028×GRIP-006、GRIP-002×GRIP-006（Robotiq 10-SPRING-PIN 与 DEVICE-CABLE-5-POLE-M8 各撞两次，同一 2F-85 重复实体加共享耦合件）；GRIP-012×GRIP-014（UR-TOOL-CONNECTOR-COMPOSITE，争用同一宿主端口）；SENS-047×SENS-37（12-PIN-ROUND-AMPHENOL，线缆端）；SENS-049×SENS-854（M8-5-PIN-SENSOR-CABLE，线缆端）；SENS-031×SENS-855（M12-5-PIN-A-CODED-IEC-61076-2-101，线缆端）[E]。

经人工 locus 重判后，8 个"可判定"对中仅 ACT-001×ACT-002 幸存为真·器件对器件互插：DYNAMIXEL TTL 总线，设计上即可菊花链 [V]。其余"可判定"对或是线缆端碰线缆端、或是重复实体、或是两器件争同一宿主端口。D3 的 1 对因此是真互插的**下界**，不是上界。

| Z1 端口耗尽 | 宿主位数 < 器件所需 | 126 对 / 240 次阻断 | 否（设计约束；P1） |

### 4.4 命题 P1 与推论

**P1（端口预算上界）。** 设宿主 h 工具侧有 p(h) 个可独立供电且独立寻址的连接器位；器件 d 若不借外部独立供电或总线则占 1 位。则同挂于 h 的独立器件数 k 满足 **k ≤ p(h)**。

*证明。* 每器件需独立通电并独立寻址；一个物理连接器位只提供一条物理通道，两器件不能共用同一物理连接器。若允许总线共享（如 DYNAMIXEL 菊花链），则 k ≤ p(h)·m，m 为该总线最大站数。∎

**C1。** UR3e 与 UR5e 工具侧 `tool_io_ports = 1`，单一 "M8 8-pin" 连接器（8 是**针数**不是位数；位 = 1）[V]。故这两台宿主上任意 k≥2 的共装问题不可满足，与两端声明完备性无关。

**C2（证据单调不变性）。** 补 Z3 或 Z4 只能把 unknown 变成 compatible 或 incompatible；它不能改变 Z1 的可满足性，后者由 p(h) 决定。"补完缺失数据、系统就能打通共装"这一纲领因此在逻辑上为假：它解决的是 unknown 对（一个问题），却不是 360 对全为零的原因。

**C3。** Franka Research 3 宿主在目录中 `tool_io_ports = null`——刻意留空，因其 datasheet 只称 "end effector connector"，未给型号与针数 [V]。其 unknown 属 Z4 而非 Z1；补证据前不可判，也不得并入结构性 Z1 计数（此条修正 v2 旧误判）。

### 4.5 法兰是套件属性，不是器件属性

三个厂商家族，据其自有文档 [V]：

- **Robotiq。** 同一夹爪（2F-85 / Hand-E / AirPick / EPick）经通用连接套件可对 31.5-4-M5 与 40-4-M6；经 UR 专用耦合件为 50-4-M6；3-Finger 仅 40-4-M6。
- **OnRobot。** 器件本身不带法兰标号；文档写的是"装到 Quick Changer"。Quick Changer 机器人侧才是 ISO 9409-1-50-4-M6。
- **ATI。** Axia 安装侧为 71.12 mm 螺栓圆、6×M5 螺纹孔，无 ISO 标号。

于是目录里 2,016 对机械"identity"判定，实质多是**套件规格同一**，不是器件可互换。两个部件共享一个 ISO 标号，可能只因买了某套件；撤掉套件，对接几何未声明。这解释了为何机械轴看似可判（295–3,240 对）而共装层仍全为零。

### 4.6 稳健性

*名称归一去重。* 合并同名重复实体后，总体为 645 节点 / 207,690 对。机械同法兰数 295 → 294；D2 的 8 对不变。量级变化 <4%；全部定性结论成立 [E]。

*补采编码一致性。* 在 101 个机械接口未声明的 EOAT 节点中，人工裁定给出 A 法兰承载 35 件（15 夹爪含 4 灵巧手 + 20 六维力/力矩）、B 体装/贴装 44 件（RealSense 相机、视触觉皮肤、LiDAR/IMU/事件相机、整机感知套件）、C 泛品类占位 22 件。关键词规则对人工裁定得 **Cohen κ = 0.6236，一致率 74.26%，26 条翻转**——低于 0.75 门槛 [E]。我们如实报告这是"规则对单人"而非"双人"一致性：真实补采 backlog 是 35 件而非 101 件；不先改编码规则就补字段只会注入噪声。

*补齐 35 件后的乐观上界。* 慷慨假设 35 件法兰承载件全部补齐、且每件新声明器件在电气轴上与其余所有 declared 器件互配。目录现有 25 个 declared 电气端口；补 35 件文档齐全的器件最多把 declared 端口池放大一个小倍数，而 D2 仍受"类型+针序+性别同时相等"约束——即便在最宽松的 D0 读数下，214,840 对里也只有 8 对。即便按最乐观补齐率，D2 密度仍低于 1%（随附 `04_ResearchData/upper_bound_calc.md` 可复算）。补采只是重分类零，不制造兼容。

### 4.7 外部清点（HRIM 与 UR+）

HRIM 仓库全树枚举 [V]：**21 个类模型**（actuator 3、composite 3、power 1、sensor 14）；**3 个实例级 datasheet**（hans_rotaryservo、robotiq_gripper_finger、xtion_depthsensor）；**0 个机械对接字段**（全树无 flange/PCD/螺栓圆/安装模型；generic 模型仅含 power、id、module_3d、module_urdf、specs_comm、state_comm、status）；**0 个连接器级电气字段**（电气只到 power.xml 的电压/电流与 specs_comm.xml 的协议——无连接器型号、无针数、无针序）。典范 gripper 类模型逐字为 `<module name="gripper" type="actuator" description="defines the messages to interact with grippers">`，其 mandatory/optional 块全是对 `topics/*.xml` 的 `xi:include`。HRIM 是**通信信息模型**——它定义与夹爪交换的消息——不是装配信息模型。它被引用八年，对接字段为零。

UR+ 市场页显示 **528 个产品**，筛选器仅 Category / Applications / Product Type / Compatibility / Region [V]。无法兰字段、无连接器字段、无针序字段。接口字段覆盖率 **0/528**。

原计划的"取 50 件外部件重算"因此不可执行：两个外部来源合计贡献零个同时带机械与电气声明的部件。这个"非结果"本身就是第三条独立证据——一个被广泛引用的信息模型与一个 528 产品的商业市场，都省略了兼容判定所需的对接字段。接口描述缺失是生态级现象，不是某一个目录的脏数据。

## 5. 讨论

**为何"补完数据"不能打通共装。** C2 说，每个产品数据项目默不作声的承诺——字段更多、判定更多——只对 Z3/Z4 成立。在 360 对层上，82.5% 的零是 Z1 或 Z5，现在就已定，不是以后才定。实践后果是：建在本目录上的配置器会诚实地对余下 17.5% 报"未知"，并对 82.5% 报"不能"，且理由是任何 datasheet 都不会改变的。

**事实标准仅限本代。** UR 工具连接器被当作工业默认，但我们的宿主侧审计显示它只在 50-4-M6 这一代（UR3e/5e/10e/16e、8 Long/15/18）成立。UR20/30 换为 ISO 9409-1-80-6-M8；官方适配器只转机械不转电气，并把载荷压到 20 kg [V]。这里的"兼容"是非二值量：机械可转接、电气不可转接、载荷代价 20 kg。

**字段名污染是系统性的。** B1 四项闭环里三项是同一故障的不同外衣：把 "ETHERNET"（协议而非连接器）写进连接器名；交付缆实为 4-pin M8 却记 5-pin；把线缆另一端 M12 记成传感器第二端口 [V]。本目录电气轴缺的与其说是数据，不如说是错置的数据——而错置数据比未知更糟，因为它能在 D0 通过标签相等检查。

**与部分约束逻辑的关系。** 配置文献把 unknown 当对称第三值 [8][9][10][11]。我们的分类学说它不对称：Z3/Z4 的 unknown 在等证据，Z1/Z5 的零已是终局。一个把两者都渲染成同一灰色"未知"的配置器，是在 82.5% 的判定上过度承诺。

**范围。** 本样本是审计目录（656 节点、329 厂商），不是市场普查；整群 CI 很宽，外推必须受限；κ=0.6236 是规则对单人而非双人；宿主侧结论仅对 UR3e/UR5e/FR3 成立；D3 的 1 对是真互插的下界。

## 6. 效度威胁

1. *样本。* 656 节点是审计目录，不是机器人硬件市场的概率样本。
2. *方差。* 按 329 家厂商整群 bootstrap 得宽 CI；点估计不应读作生态级比率。
3. *评分者。* B2 的 κ=0.6236 是自动规则对单人裁定，非双人。
4. *宿主。* 宿主侧数字基于三台宿主（UR3e、UR5e、FR3）；外推到其余臂需相应 datasheet。
5. *下界。* D3 仅一对真互插，真互插率以 0.00047% 为下界；在更精编目录中可能更高，但本文主张的是阶梯的*结构*。

## 7. 结论

在固定的 656 可组合节点、214,840 对总体上，可判定电气对的占比随证据门槛收紧从 64.764% 移到 0.00047%——五个数量级，驱动力是 528 个占位端口自匹配。电气轴在每种定义下均为最弱轴。共装层上，82.5% 的零是结构性的（端口预算或角色不互补），并由 P1 证明与数据完备性无关地不可满足；其余零在原理上等待证据。最主要的信息模型（HRIM）与最主要的市场（UR+，528 产品）都省略了这些判定所需的对接字段。兼容性不是更好数据就能打开的门；它是一个答案取决于门槛的测量，而其零的上界是结构性的。
